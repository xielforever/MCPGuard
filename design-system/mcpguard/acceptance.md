| 能力 | 当前证据与页面边界 |

| 旧内嵌控制台 | 已有真实本机登录、审批、资源、规则、用户组、本人审计和通知状态；迁移要保留全部功能 |
| 多资源目录与独立身份 | RA-01/02/03 本地切片已有基础；正式新资源业务执行仍需后续执行阶段 |

| 密文包、私有交付、Context、适配器 | RA-07 至 RA-10 有本地记录；安全元数据、私有能力和真实客户端验收分开 |
| 正式新资源读写、全面吊销、在途停止与轮换 | 按 RA-11 至 RA-15 的各自实现与证据开放；本规范不提前宣称完成 |

## 3 已知规范迁移缺口

| ID | 差异 | 处理要求 |
| --- | --- | --- |
| UX-G01 | 旧受控写决定只接收 `vote/planHash`，不能保存文本理由 | 目标拒绝理由规则需要版本化契约补齐后再实现；保留旧入口已有行为，不发送未知字段，不把草稿说成已存审计 |
| UX-G02 | D/E 预览理由选填；资源权限当前 `DecisionInput.reason` 必填，批准另需期限 | 正式资源权限表单按当前契约；预览保持历史，不作为字段规则来源 |
| UX-G03 | 预览中存在样例身份切换、固定时间与计数 | 正式页面移除演示切换；身份、时限、统计来自当前受权数据 |
| UX-G04 | 新领域事件与旧本人审计入口尚不能据此声称完全统一 | 先按实际来源分区/关联；后续具备真实汇总接口后再统一展示 |
| UX-G05 | 控制台到客户端私有组件的动作桥接需实际宿主能力 | 不把 Cookie、URL 或页面 JS 当作私有证明；无桥接能力显示安全手动路径或不支持 |
| UX-G06 | 完整吊销影响与停止/清理结果依赖后续能力 | 按作用域与证据逐项展示；没有对应变更 API 不创建成功占位按钮 |
| UX-G07 | 两套前端尚未加载正式数值单源 | 后续从 tokens 导入/生成共享样式并桥接 Element Plus，不手抄两个主题 |

## 4 后续页面实现顺序

1. 接入 `tokens.json` 的统一语义主题，完成按钮、表单、状态、表格、确认框、反馈和导航桥接；先能在两种渲染方式中对照。
2. 迁移当前内嵌控制台的现有六个入口，用原真实接口证明权限与行为保留；旧报告与数据不重置。
3. 按既有 RA 依赖补资源申请、开通、凭据与客户端页面；只有后端能力具备且有真实 API 证据时开放操作。
4. 在全面撤权/在途与清理能力就绪后完成影响确认和处置页面，不把单文件关闭扩大宣称为所有授权撤销。
5. 统一 Vue 历史原型的基础主题或明确其只作历史展示；它不能静默成为真实控制台入口。
6. 完成页面真实联调、故障与视觉验收，再按原 RA-17/18 进行迁移/真实客户端证明。没有本规范新增的独立重复评审门槛。

## 6 规范交付本身的检查

本轮可以检查的项目是：文档链接、JSON 解析、token 引用、配色对比度、状态映射与机器枚举精确对应、来源版本、旧候选与契约字节保留、索引追加和源清单完整性。

静态检查结果单独存放于 [v1.0 规范检查目录](validation/2026-10-29-v1/README.md)。它不触发服务重启、不访问业务数据库，也不把任何 `UI-D-* NOT_RUN` 更新成已通过。
