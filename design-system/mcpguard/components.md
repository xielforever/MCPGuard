# 共用组件规范

版本：1.0.0。全局规则与数值见 [MASTER.md](MASTER.md) 和 [tokens.json](tokens.json)。本文件是实施规格，不表示组件已经接入现有页面。

## 1 组件通用规则

每个交互组件必须定义：使用场景、默认/悬停/焦点/禁用/加载/错误状态、键盘方式和异步结果。状态以真实数据驱动；不能把动画结束、关闭弹窗或 HTTP 200 当成业务完成。

同一组件在内嵌控制台与 Vue/Element Plus 页面保持相同语义与视觉角色。框架的默认蓝色、尺寸和状态标签需通过共享 token 桥接，不能在各页面直接覆盖为不同值。

组件名是设计职责，不要求本次创建同名代码。后续可复用现有框架组件，但必须满足以下行为。

## 2 Button：主要、次要、危险与文本操作

| 变体 | 使用 | 视觉 |
| --- | --- | --- |
| Primary | 当前决策区唯一主要操作，如提交申请、批准此计划 | 青色底、深色文字；不以绿色暗示执行已成功 |
| Secondary | 取消编辑、查看详情、核对状态 | 输入底色、可辨识边框与正文色 |
| Danger | 拒绝、吊销等决定；确认层明确危险影响 | 红粉色文字/边界；配明确动词，不能只有红色图标 |
| Text | 辅助导航、非主决定、展开高级信息 | 链接色或次级色，有可辨识悬停与焦点；仍保留点击区域 |

标准高度 40px，小型 32px，大型 48px；手机主要动作至少 44px，推荐 48px。桌面行内操作不得通过极小文字缩到 24px 点击区域以下。图标与文案间隔 8px。

| 状态 | 表现与行为 |
| --- | --- |
| Default | 动词具体，说明作用对象；表单外按钮显式 `type="button"` |
| Hover | 160ms 内改变底色/边框/有限边缘光，不移动按钮、不改变宽度 |
| Focus | 3px 实线焦点、4px 偏移；不能只用辉光表示焦点 |
| Disabled | 原生禁用语义，保留可读文字；在邻近区域给出禁止原因，不能只靠 tooltip |
| Loading | 文案变为“正在提交决定”等具体动作，保留宽度并禁用重复提交 |
| Error | 回到与真实提交结果对应的可用性；结果不明时不能恢复为可新建命令的普通按钮 |

“刷新”只读取；“批准”只提交决定；“查看核对记录”不重放；“关闭这个文件”与“撤销此资源授权”不能共用模糊的“撤销”文案。

## 3 Field / Form：表单与验证

- 桌面输入高度 40px、手机 48px；手机输入文字 16px，正文与帮助文字遵守最小字号。
- 标签始终可见并关联控件；占位符是示例，不代替标签。必填项同时用文字/符号说明。
- 申请人只读且来自当前认证上下文；资源、权限套餐与期限选项来自可信目录，不能输入任意 SQL、GRANT、账号密码或临时连接串。
- 在失焦及提交时验证；不为每次键入发远程请求。错误放在字段下并通过 `aria-describedby` 关联。
- 多字段提交失败时聚焦错误摘要，并提供到字段的链接；保留非敏感输入，不自动清空理由。
- 字数、范围与时间上限遵从当前契约。资源申请的 `DecisionInput.reason` 当前为 1–500 字符；批准还需要有效的 `approvedExpiry`，且不能扩大原申请期限。
- 只读与禁用有不同语义：冻结计划可读可选取，禁用字段不允许编辑。长 JSON 安全文本呈现，不能作为 HTML 或脚本执行。
- 原生日期、下拉与键盘操作优先；时间显示用户时区并可查看原始时间。倒计时不构成服务端到期事实。
- 登录允许密码管理器、粘贴与自动填充；不得要求把数据库密码、MCP token 或 Context token 粘进网页来“修复权限”。

新旧审批命令的理由能力不同，必须按 [workflows.md](workflows.md) 的兼容性要求处理，不能把尚未提交的前端理由伪装成已存审计理由。

## 4 RequestQueue / DataTable：队列与数据表

请求队列显示：申请类别、资源与短 ID、申请人、当前阶段、更新时间。选择基于稳定对象 ID，不基于数组下标、可重复别名或显示名称。资源名称相同也必须通过类型、归属、短 ID 和范围区分。

表头高 40px，常规数据行至少 48px；高密度桌面表可用 40px，但不能缩小必要点击区域。单元格默认左右/上下 12px。多行内容允许增高，不为了对齐裁掉关键资源与状态。

| 交互 | 规则 |
| --- | --- |
| 搜索/筛选 | 保留输入焦点；过滤后无结果显示“没有匹配项”，不说“没有权限” |
| 选择 | 同时有选中底色、边缘标记及语义状态；读取详情时先明确加载，不保留上一条内容假装当前条 |
| 分页 | 使用服务端游标；默认目标页量 20，但不能超过具体接口限制；不拼接不同身份、版本或过滤条件的结果 |
| 排序 | 只开放服务端支持的字段；表头支持键盘，标明当前方向 |
| 横向滚动 | 限定在有名称、可聚焦的区域；提供滚动提示，不让整页溢出 |
| 刷新 | 显示观察时间与错误；刷新失败不把旧状态变为“最新”，不自动更改选择对象 |
| 批量操作 | 只有业务接口明确支持才开放；逐项列出范围与结果，不把一次请求解释成所有成功 |

账号权限、文件、客户端和业务记录不能凭同名资源自动合并。默认空选择时不把第一条资源隐式选成业务执行目标。

## 5 Status / Notice：状态与持续提示

状态标签最小高度 24px、文字 12px，文字与符号并列。对象与状态一起表达，例如“授权已生效”“Context 已到期”“文件租约已撤销”，而不是页面上出现多个含义不明的“ACTIVE”。

状态文案以 [state-labels.json](state-labels.json) 为映射依据。映射只翻译事实，**不能从标签颜色或枚举独立推算动作权限**。对象的当前资格、完整详情、期限、版本与后端能力共同决定操作是否可用。

状态色固定映射：`info` 使用青色文字/选中底，`neutral` 使用辅助文字/提升层，`success/warning/danger` 使用各自的语义前景与底色。它们均在 token 中定义，页面不能另加默认蓝、灰或红。

Notice 用于持续影响后续动作的说明：待他人审批、版本冲突、未知结果、失去权限、私有交付待完成等。未知结果、撤销影响和无法校验资格不能只显示短暂 toast。

同时显示业务阶段、派发证据与副作用。比如“请求失败 / 已派发 / 影响未知”必须完整保留，不能收敛为“失败，无变更”。

## 6 ReviewPanel / Diff / FrozenArguments：审阅区

审阅内容的优先级为：申请人 → 精确资源/范围 → 操作/权限 → 具体变化 → 上限与期限 → 版本/来源 → 决定记录。D 的轨道图属于辅助层，不能遮挡或取代这些事实。

差异对照显示“变更前·观察时点”和“变更后·申请内容”，同时列出执行前置条件。仅有申请参数时显示“未取得可对照快照”，不能编造原值。标记删除与新增使用 `−/＋`、标题和文字，不只用红绿。

冻结参数采用只读、可滚动的代码面板；原始业务结果与脱敏计划分开。长数据按接口的截断/分页标记展示，不用前端省略冒充完整计划。无法获得足够决策细节时关闭批准入口。

详情标签支持方向键、Home/End；提供正确 tab/tabpanel 关系。切标签不重新提交申请，不重建身份上下文。

## 7 AuthorizationOrbit：授权关系图

| 项目 | 要求 |
| --- | --- |
| 语义 | 申请人、冻结申请、当前审批阶段、精确目标资源；数据必须对应当前选中对象 |
| 主形 | 中央几何闸门与低对比轨道，青色用于当前关系，待定/未知有明确状态文字 |
| 装饰 | 细网格、局部标尺、缓慢旋转；不携带授权事实，不生成随机业务数字 |
| 证据边界 | 图上连线不代表网络连通、授权成功或已派发；不得写“实时”而没有当前数据来源 |
| 辅助技术 | 提供简短关系说明；必要字段在文字区域完整存在；装饰 SVG 子元素不逐个进入焦点序列 |
| 窄屏 | 可缩减为中央阶段符号，身份和资源保留在相邻文字摘要；不能把关键字号整体缩到不可读 |
| 状态变化 | 只更新当前对象的图形与文字；不因背景旋转重置焦点、表单或选择 |

只有存在真实可导航节点时才做交互节点，并提供等价按钮/列表。没有业务动作的轨道不伪装成可点击的复杂控件。

## 8 DecisionPanel / Dialog：决定与确认

决定区持续展示：对象阶段、当前人员是否可决定、实际影响、期限和下一步。批准与拒绝不自动进入浏览器执行；无资格时原因必须在区域内可读。

确认框默认宽 520px、复杂影响可用 720px，视口四周至少留 16px并允许内部滚动。背景遮罩明确隔离上下文，不能只靠模糊。确认框必须重新列出申请人、资源/范围、关键变化、期限与决定影响；不能只问“确定吗”。

| 类型 | 确认内容 |
| --- | --- |
| 受控写批准 | “只记录决定；原申请者仍需显式恢复”；绑定当前冻结计划 |
| 资源账号权限批准 | 批准的套餐、范围、期限与理由；“批准不等于开通或已激活” |
| 拒绝 | 当前申请及拒绝影响；目标规范要求理由，按当前契约能力提交 |
| 文件/租约关闭 | 当前用户、资源、文件短 ID、其他文件是否受影响 |
| 授权级撤销 | 此授权关联的文件、客户端激活、在途状态与原生清理分别列出 |

打开后焦点进入标题/安全首控件，Tab 留在确认框内。Escape 与取消不提交。关闭后回到可见且仍有效的触发控件；对象已失效则回到标题或列表。不能依赖动画结束事件决定是否保存。

确认只对打开时的版本有效。确认期间数据刷新、权限变化或计划失效时，保持说明并使提交不可用，要求重新审阅。理由不自动迁移到新计划。禁止用“长按批准”、反复输入密码或装饰性勾选代替真实权限校验。

## 9 Loading / Empty / Error / Toast

| 状态 | 文案与动作 |
| --- | --- |
| 初次加载 | 骨架/不定加载和“正在读取申请”；不展示虚构样本与默认成功计数 |
| 已提交等待响应 | 显示正在提交的具体决定；按钮禁用，维持原命令键 |
| 无数据 | “暂无待你处理的申请”；只在接口成功返回空集后展示 |
| 筛选为空 | “没有匹配的申请”，提供清除筛选 |
| 无资格/功能未开放 | 说明当前权限或能力边界；与空数据分别处理 |
| 网络失败 | “未能取得最新状态”，保留必要安全关联和观察时间；不能推断业务失败或权限已撤销 |
| 提交结果未确认 | 持续提示并核对同一命令；不能提供创建新决定/重放业务的直接按钮 |
| 后端明确拒绝 | 展示脱敏原因、对象 ID 和允许的下一步 |

Toast 用于可逆、非关键完成反馈，约 4.8 秒，可手动关闭；使用礼貌 live region，不移动焦点。关键状态始终在主内容中保留。业务错误与原生认证错误分开，不要求用户因数据库密码错误反复登录网关。

## 10 Pagination / Copy / Notification

复制仅限当前有权查看的安全 ID、版本、脱敏说明和继续指引。复制成功给出短反馈；不能复制完整凭据、认证头、未经脱敏原始异常或免认证链接。

通知页与通知消息只提供安全摘要和需再次认证的入口。通知发送成功不改变决定状态，通知失败不让审批降级为模型自批。

计数必须有范围和观察时间；未读到时显示“—/尚未取得”，不能显示 0。没有数据来源时不显示“在线客户端数”“全部已吊销”等仪表数据。

## 11 Checkbox / Radio / Switch：选择与启停

勾选框/单选图形为 20px，连同可点击标签至少提供 44px 目标区域；标签间隔 8px，同组间隔 12px。使用原生状态语义，空格切换勾选，单选组支持方向键，禁用状态有邻近原因。支持未选、选中、部分选中、焦点与禁用状态。

选择当前表单中的权限选项不等于已经授予权限。主体/资源授权的改变先显示具体范围与影响，再按业务命令提交，不能让一个无说明的开关立刻代表授权已成功。

Switch 只表示清楚、二元且接口支持的配置启停，不表达审批、原生账号开通或清理进度。提交期间锁定当前意图；服务端明确成功后才显示新权威状态，失败/冲突要恢复到实际状态并说明。资源停用可能影响未执行计划时，使用已有受控配置流程列出影响，不隐含召回已派发操作。

## 12 Navigation / Tooltip / Overlay：导航与叠层

紧凑导航图标同时提供 `aria-label`、当前项语义及悬停/键盘焦点说明；展开后持续显示文字。Tooltip 不承载唯一关键业务信息，不作为确认资格的唯一原因说明。

下拉、选择面板、日期面板、提示与确认框统一继承 D 的语义颜色、字号和焦点。渲染到页面根部的浮层也要继承主题，不能因框架默认样式出现白底白字、默认蓝色主操作或不可读的菜单。

主操作使用浅青色时必须同时映射深色 `onPrimary` 文字；不能沿用框架默认白字。框架警告、成功与危险标签使用各自的前景/底色配对，不只替换一个主色变量就视为全部主题完成。
