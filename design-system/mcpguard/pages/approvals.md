# 页面规范：操作与审批

版本：1.0.0。继承 [MASTER](../MASTER.md)、[共用组件](../components.md)与[跨页流程](../workflows.md)。页面逻辑标识用于设计，不承诺本次新增真实路由。

## 1 页面职责与视角

审批舰桥用于定位请求、核对冻结计划、由合格他人记录决定，并据实际证据查看后续结果。它不承担任意 SQL 编辑、共享管理员切换或由审批人代为执行。

| 视角 | 列表与详情 | 决定及执行 |
| --- | --- | --- |
| 申请人 | 当前有权查看的本人申请与结果 | 不可自批；取消及后续继续只按既有服务端资格与入口 |
| 合格他人 | 当前审批范围内的请求及足够审阅的授权细节 | 只可提交当前计划的批准/拒绝；不因审批资格获得业务读取权 |
| 运维核对人员 | 当前对象范围的计划、执行/开通证据与核对记录 | 仅调用明确支持的核对/处置入口；不重放未知业务 |
| 无对象权限者 | 不显示受限参数、结果及存在性细节 | 不提供决定或共享身份入口 |

## 2 请求舱：定位当前对象

分类筛选至少区分受控操作申请和资源账号权限申请；我的申请、待我处理、待核对不能混成一种“待审批”。分类计数来自对应当前范围，没有当前数据时显示“—”。

请求行显示：类别、标题、申请人、资源名与短 ID、范围、当前阶段、服务端时间。相同资源名要能辨认真实资源。资源申请编号与 Action ID 有独立标签，不能把 requestId 当 actionId 传给旧接口。

默认优先展示待当前人员处理的记录，具体排序遵从接口能力。搜索与分页有界；切换筛选、账号或组织后重置游标。请求详情在加载中明确显示目标和加载状态，上一条内容不得短暂冒充新选择。

## 3 授权轨道与审阅面板

顶部给出“谁为谁决定”的明确说明、对象类型、编号、阶段及观察时间。中央轨道关联申请人与精确资源，阶段文字必须和服务端当前快照一致；装饰旋转不推动业务阶段。

### 3.1 受控写

必要内容：

- 当前可信申请人与组织/范围。
- 工具/原生操作、精确资源、目标条目和可公开的实际身份关联。
- 冻结参数及关键变化；没有快照时明确“无可对照快照”。
- 预期版本、影响上限、配置/工具/计划版本、expiresAt。
- 目前决定、是否存在执行资格、派发状态和副作用状态。

标签提供“变更内容 / 冻结参数 / 决定轨迹”。参数不可在审批中修改。完整细节被截断、失效或无法授权读取时，不允许盲批。

### 3.2 账号与权限

必要内容：资源 ID/版本、申请人、权限套餐/版本、数据范围、申请用途、请求期限及可批准期限。不得输入原生权限 SQL。批准范围和期限只能保持或收窄，原申请仍不可变。

决定、开通任务与 AccessGrant 三个区域分别呈现。批准不自动变成“账号已创建”，开通已核验也不直接等于客户端访问已激活。

### 3.3 时间与证据

到期依据服务端时间。D 样例中的“30 分钟”不成为产品默认期限。倒计时到零或时钟不可信时暂停决定并刷新，不把本地时钟结果写回权威状态。

时间线记录来源、主体、决定、版本和时间；“尚未发生”与“未取得记录”分开。不得用插图或占位成功事件填补空白阶段。

## 4 决定舱与可用性

决定区保持对象名称、当前阶段、目标范围、期限、决定影响和当前身份资格可见。实际按钮还需服务端支持该动作，不凭本表推导绕过资格。

| 条件 | 操作与说明 |
| --- | --- |
| 当前合格他人、计划有效且必要细节完整 | 可批准/拒绝，确认层绑定当前对象/计划/版本 |
| 本人申请 | 无自批入口或禁用，说明“本请求须由其他合格人员审批” |
| 资格已失效/未能重新校验 | 暂停决定；明确已拒绝与网络未确认的区别 |
| 计划/配置/期限变化 | 要求重新审阅，不在确认层静默替换计划 |
| 已批准、尚未恢复 | 只显示对应后续指引；后续否决仅在已有接口明确支持时提供 |
| 已进入执行或已结束 | 不追加批准改变事实，不出现“审批后立即重做” |
| 未知结果 | “请勿重复提交”，只提供有资格的证据核对入口 |
| 接口/版本不支持此操作 | 明确未开放；不能用 toast 模拟成功 |

## 5 确认与提交

确认层再次列出申请人、资源/范围、关键变化、期限及下一步。受控写主按钮为“批准此计划”，资源权限为“批准此权限申请”；拒绝明确写“拒绝此申请”。不能只用“确认”表示不同后果。

资源权限决定的理由必填并按当前 1–500 字符限制，批准还需合格期限。旧受控写理由字段的兼容性缺口见 [验收清单 UX-G01](../acceptance.md)。字段不受支持时不得发送未知载荷，也不得声称已保存。

提交期间固定对象和用户意图，禁用重复提交，保留同一幂等键。服务端明确响应后再更新决定；网络中断时先核对命令，不能先显示“批准成功”。请求头/字段格式由相应契约适配，不将旧 `vote/planHash` 与新 `decision/requestHash` 混用。

## 6 执行、取消与结果未知

批准后的主要说明为“已批准，等待原申请者显式恢复”。可复制的继续指引仅包含安全编号与操作步骤，不包含凭据、敏感参数、审批证明或新 SQL。

取消未派发请求时，可据真实结果显示“已取消，未派发”。取消已派发操作只显示“取消请求已受理，正在确认结果”，不能显示“已回滚”。

未知页同时给出：原请求/计划、派发证据、原生关联、可能影响、观察时点与仍未知的部分。核对不产生新执行资格。字段值等于目标值、操作员手写备注或网络恢复，都不单独证明原操作是否完成。

## 7 窄屏与键盘

宽屏三栏，空间不足时按 MASTER 降级。手机先给出当前申请摘要与阶段，再查看冻结细节和决定；队列可折叠，不要求滚动很多历史记录才能知道当前审批目标。

标签支持方向键/Home/End；队列与决定支持 Tab/Enter。打开确认层后保留必要背景上下文，关闭返回触发控件。视口变化只调整布局/图形，不重建表单或丢失理由。没有任何动作只依赖鼠标悬停、长按或拖拽。

## 8 本页验收重点

同名双 PG 不混选；Alice 不能看到 Bob 的越权详情且不能自批；权限撤销与计划变化使按钮及时失效；409/412、断线、重复提交与乱序响应可正确解释；批准不派发；未知不重放；手机和 200% 缩放保留完整决策内容。
