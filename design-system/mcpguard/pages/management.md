# 页面规范：全局管理与通用页面

版本：1.0.0。继承 [MASTER](../MASTER.md)、[组件](../components.md)和[跨页规则](../workflows.md)。全局保持 D 的深空、青色语义主题；非审批页面不必堆放轨道图来制造科幻感。

## 1 登录与工作空间

保持独立浏览器登录。登录页清晰展示执契、当前部署/工作空间说明和支持的身份方式；不得将 MCP Bearer、Context token 或数据库密码作为网页登录输入。

字段有可见标签，密码管理器/粘贴可用；错误使用脱敏的登录失败原因，不泄露具体主体是否存在。真实 SSO 尚未接入时标明当前本机身份模式，不画已连接企业 IdP 的绿色图标。

退出后清除当前页面状态与敏感草稿，返回登录；重新登录须重新鉴权对象。无权限与会话失效分别解释，不尝试共享管理员凭据。

## 2 导航与页面结构

| 逻辑入口 | 主要内容 | 页面不能暗示的能力 |
| --- | --- | --- |
| 操作与审批 | 我的操作、待我处理、详情、结果核对 | 管理员可代发业务、本人可自批 |
| 资源目录 | 当前可见资源和可申请套餐 | 类型/名称相同就可跨资源访问 |
| 我的账号权限 | 申请、决定、开通与 Grant | 已批准即已开通 |
| 凭据与客户端 | 安全元数据、私有交付、Context 与多资源激活 | 浏览器/MCP 可以读取私有令牌 |
| 策略规则 | 当前规则、范围、版本与生效说明 | ALLOW 能授予缺失权限或跳过写审批 |
| 用户与权限 | 当前管理范围的用户、组、成员及授权 | 显示角色即可修改可信身份 |
| 本人审计 | 本人/明确受权范围内的事件 | 管理或审批自动获得全组织审计导出 |
| 通知与设置 | 通知配置状态、身份接入状态与安全说明 | 通知成功即批准成功、配置存在即服务健康 |

菜单按能力和当前权限组织，逻辑入口可在现有六个页面中分组；不在设计阶段承诺新增路由。未开放能力显示原因，不能使用无处理器按钮或空白页冒充已实现。

## 3 策略与工具

策略列表展示当前效果、目标工具/资源、匹配范围、启用状态和版本。拒绝优先；规则允许不授予缺失的工具/资源权限。不能临时“降低风险”使当前待批计划绕开限制。

管理编辑先展示差异与受影响对象，保留版本条件和幂等语义。成功后刷新相关计划状态；旧计划失效时重新申请，不能在原计划上静默换配置。

工具候选版本、网关当前发布与客户端快照分别表达；不能仅因网页保存成功就说客户端目录已更新。没有任意 SQL、Redis 命令或任意 URL 调用面板。

## 4 用户、组与权限

表格区分：身份是否有效、业务读取、工具授权、资源审批资格、控制台管理权限。普通角色文字不能代替实际细粒度授权。组成员与组是否启用分别显示，主体明确拒绝与组授权的组合以服务端结果为准。

更改前列出具体用户/组、资源/工具、授予或撤回方向和预期影响。当前身份丢失管理权后立即停止编辑、清除受限详情，不能维持之前打开的表单继续提交。

原生账号与员工名可以不同；只展示受权、安全关联。不显示角色密码、SecretRef 或其他用户的缓存路径。委派新权限仍按既有业务授权与审核路径，不因本规范新增便捷入口。

## 5 审计与历史

展示事件类型、对象、可信主体、资源、版本、服务端时间和安全关联 ID。决定、开通、交付、激活、派发、副作用、撤销与清理是不同事件，不合并为一个“操作成功”。

默认本人范围；更广查询与导出必须有独立权限和接口支持。当前 `access_audit` 与旧 `audit.list` 未统一时，按数据来源分区，不伪造一条已汇总的完整时间线。

过滤条件与分页遵从接口，未读到的页不能估算总条数。错误、过期游标或组织切换不能拼接旧事件。原始报告、失败和后续核对记录保持追加，不能用最新成功覆盖旧失败。

日志详情先脱敏，以文本展示；复制只提供安全关联信息。导出没有现成能力时标为未开放，不从前端内存偷偷导出所有敏感行。

## 6 通知与设置

通知状态区分未配置、待发送、重试中、已确认送达和最终失败，且必须有可信数据。未配置 Telegram 时明确“审批无需依赖通知送达”，不把配置缺失显示为业务无法审批。

配置页只显示安全状态、版本和允许修改的字段。秘密经受支持的私有运维路径管理，普通网页不增加“显示当前密钥”。测试通知只有真实接口和明确目标存在时才可用；设计预览不发送消息。

主题默认 D；“关闭动效”是视觉偏好，不改变授权、认证或业务状态。偏好只存非敏感值，不能把 token、当前计划、凭据与结果混入持久偏好。用户/工作空间切换后按范围使用偏好。

## 7 当前页面迁移约束

当前内嵌控制台的六个入口仍需完整覆盖，既有登录、批准/拒绝、资源启停、规则、用户与用户组、本人审计和通知状态不能因视觉改版丢失。

`web/` 历史原型中的静态指标和占位保存不是实际数据源。迁移基础主题时保留原型说明，不能把它作为新控制台上线；真实能力必须在实际受保护 API 上验收。

科幻装饰集中在应用标识、选中层、分区和必要关系图；规则、用户和审计页面以清楚的表格、版本和可读文本为主。这样不同页面使用同一系统，也不会因每页都加“仪表盘”妨碍业务操作。
