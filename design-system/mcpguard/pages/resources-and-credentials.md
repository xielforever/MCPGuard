# 页面规范：多资源、账号权限与凭据

版本：1.0.0。继承 [MASTER](../MASTER.md)、[共用组件](../components.md)和[跨页流程](../workflows.md)。这些页面属于目标界面规范；当前 API、开关和实施阶段见 [acceptance.md](../acceptance.md)，不能把设计完成写成功能完成。

## 1 资源目录与详情

目录显示当前主体可见资源，而不是所有组织的资源或 MCP 协议 `resources/list` 的替代品。字段包含类型、名称、短资源 ID、归属/用途、当前可申请套餐、资源版本、启用状态和本人授权摘要。资源别名、类型和显示名均不能单独作为调用目标。

两套 PG 的选择必须可核对：名称 + 类型 + 短 ID + 范围 + 配置版本。详情页保留完整安全 ID，复制仅复制安全 ID；不显示连接串、密码或秘密引用。

| 操作 | UX |
| --- | --- |
| 查看资源 | 只读取当前受权安全视图；不自动连接数据库 |
| 申请访问 | 仅在当前 `canRequest`、资源状态与实际能力允许时显示；套餐来源可信目录 |
| 检查连接 | 仅供有资格人员对已登记配置使用已有受控检查；不输入临时 URL/DSN |
| 资源启停/版本变更 | 展示配置差异、受影响工具及旧计划可能失效；服务端提交确认后更新 |

“已登记”“配置存在”“最近检查通过”“当前可访问”是不同事实。健康状态应有来源和观察时间，未知时不放绿色在线指示点。

## 2 我的账号与权限

按资源列出本人申请、决定、开通任务、原生账号管理模式与当前 Grant。可公开原生用户名时仍须服务端授权，不公开其他用户的账号列表、秘密或绑定配置。

申请步骤：选择精确资源 → 选择最小权限套餐 → 明确范围与用途 → 选择允许的期限 → 核对并提交。申请人只读；不让用户手工填写 ownerId、nativeIdentity、GRANT SQL 或角色密码。

已存在账号须明确是“登记的既有账号”还是“本申请新建的托管账号”，避免把既有账号当成可自动删除的对象。批准、核验和 ACTIVE 分别留痕，未知开通显示原任务核对，不出现“换个用户名再建一次”。

原申请范围不可在审批详情悄悄变更。新范围/新期限是新意图，按契约处理新申请或明确的后继关系；旧决定与失败记录保持不变。

## 3 申请与开通进度

详情分成四块：申请快照、审批记录、开通任务、当前授权。头部主状态有明确对象前缀，避免把 `AccessRequest.APPROVED` 当成 AccessGrant 的当前有效性。

| 当前事实 | 建议主文案 | 下一步 |
| --- | --- | --- |
| 申请待批 | 等待合格他人审批 | 查看/按资格取消，不自批 |
| 决定批准，授权处理中 | 已批准，账号权限开通中 | 查看开通记录，不准备不可用凭据 |
| 开通结果未知 | 开通结果待核对 | 核对原任务，无新建账号按钮 |
| 核验完成且 Grant ACTIVE | 授权已生效 | 在当前能力允许下准备私有交付 |
| Grant 终止 | 授权已撤销/到期/开通失败 | 显示原因与历史；新申请不复活旧授权 |
| 清理待处理 | 授权终止，原生清理待完成 | 分别显示清理证据与人工处置需求 |

进度条表示真实阶段，不展示虚构百分比。若只获得部分对象状态，对其他阶段显示“尚未取得状态”，不能自动填成功。

## 4 我的凭据：安全元数据视图

列表行至少关联：资源、本人账号/授权安全标识、credentialId、leaseId、状态、到期时间、后继关系与交付状态。文件有效性、是否已本地接收、是否在某客户端激活分别显示。

普通页面不显示密文字节、nonce/tag、认证 token、SecretRef、DSN、密码和可免认证 URL；不提供解密按钮、凭据全文复制或上传到聊天。包不含数据库密码也不改变私有交付边界。

“关闭本文件”必须与“撤销资源授权”分开：前者限定该文件/租约，后者影响关联权限、文件与激活。两种确认框均先列出影响范围，不能用相同“撤销”按钮让用户猜。

自然续期形成后继包/租约，显示旧→新关系。旧租约到期不被改回 ACTIVE；被撤销包不提供“重新启用”。本地文件损坏或缺失由安全客户端流程恢复，不通过网页粘贴原文件内容。

## 5 下载准备与私有领取

根据真实客户端能力选择文案：

- 已登记且支持私有交付：显示具体客户端安全标识与“交给此客户端私有领取”。
- 只有手动路径：显示“查看安全领取步骤”，明确还需要本人认证及受支持私有组件。
- 无私有能力：明确“不支持自动私有领取”，不能把 URL-only 配置显示成全自动。

准备完成仅显示安全交付编号与期限。`READY` 为待领取，`CLAIMED` 为领取资格已消费；只有可信客户端完整接收/校验的状态才能显示“已接收”。

消费后响应丢失时显示核对状态，恢复可创建替代 ticket 交付同一仍有效包；界面须明确“不创建新账号、不重新开通授权”。真实接口没有返回可确认的结果时，不通过新申请或页面刷新来猜测。

网页不复用浏览器 Cookie 越权调用私有 claim，不把私有令牌放入 URL、DOM、可复制日志或模型可见工具结果。下载进度只在有可信字节总量时显示百分比，否则显示接收/校验阶段。

## 6 凭据与客户端总览

每个客户端显示可信登记 ID/安全标签、入口类型、最后确认时间、Context 状态、有效期及各资源激活。名称“我的电脑”不构成可信客户端身份，页面不显示私有令牌。

| 层级 | 必要显示 |
| --- | --- |
| 当前人员 | 登录/认证可用性、组织、主体安全标识；不展示员工 token |
| 客户端登记 | 已登记/登记撤销；不把已登记等同在线 |
| Context | ACTIVE/EXPIRED/REVOKED、相应恢复方式；短期与绝对期限按接口信息区分 |
| 资源激活 | resourceId、所选 credentialId、安全状态与观察时间；多资源分别列出 |
| 私有同步 | 待同步、已处理回执或未支持；网页不假装启动后台 worker |

界面根据 `ClientAdapterCapabilities` 的真实字段说明：HTTP helper 可能需要宿主重新连接以更新头；stdio 私有适配可在下一次远程请求前恢复自然到期；显式撤销的 Context 需要私有修复。能力声明不能替代某个真实 coding 产品的端到端验收。

同一 Context 中只关闭某资源激活，不默认关闭其他资源。当前用户/组织改变后，旧 profile、Context 和激活不自动继承；不能从历史文件里随机选择一个包恢复可用。

## 7 吊销与处置详情

操作入口先明确目标类型与当前用户的管理范围，再给出具体对象。授权级、文件级、Context 级、用户级或资源级不能混在没有作用域说明的按钮里。

详情至少展示三列事实：网关拒绝后续访问是否已提交、在途停止是否已确认、原生清理是否完成。每列保留观察时间与来源；未知不填 0，不把“网关已拒绝”写成“数据库账号已删除”。

客户端离线时，界面仍依据服务端撤权事实显示后续拒绝，不等待本地文件被删除。后续私有同步处理本地状态，不允许重新激活已撤销权限。外部既有账号的处理范围必须明确，不能自动接管或删除。

## 8 本页验收重点

同名双 PG 的目标选择、Alice/Bob 隔离、申请批准与 ACTIVE 分离、开通未知不重建、CLAIMED 与收到文件分离、两客户端不串任务、单资源失效不误伤其他资源、自然续期与撤销不复活、不同吊销范围及在途/清理分别显示。
