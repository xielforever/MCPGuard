# MCPGuard 整体 UI 重设计：视觉方向草案

日期：2026-10-29。状态：**方向待用户选择；未实施到业务页面**。

用户在统一 UI 的范围选择中明确要求“整体重设计，先看多个视觉方案再选”。本目录将同一组业务场景做成三个可以浏览的高保真方向，供选择导航、信息层级、阅读密度和组件语言。

用现代浏览器打开 [单文件离线预览](preview-offline.html)，即可切换三种方案和六个业务场景；通过“查看组件与状态”对照基础组件。也保留 [拆分源码入口](index.html)。页面不依赖 npm、外部字体、CDN、图片或服务端 API。本次本机 HTTP 入口受执行环境网络限制，浏览器验证采用离线文件；不将 HTTP 或内置浏览器打开失败记录为成功。

## 方案对照

| 方向 | 页面结构与阅读方式 | 视觉基础 | 适用重心 | 取舍 |
| --- | --- | --- | --- | --- |
| A 青墨 · 资源工作台 | 左侧全局导航；中间队列/表格；右侧请求详情。资源管理、身份和审计可逐步扩展 | 青墨侧栏、冷白工作面、青绿色主操作；系统中文无衬线字体；6px 组件圆角 | 资源管理、日常申请与审批并重 | 页面间切换明确；同时打开详情会占用部分列表宽度，较窄视口改为上下布局 |
| B 纸白 · 审批案卷 | 横向全局目录；左侧案卷索引；右侧文档式审阅。申请身份、冻结参数、审批影响分段呈现 | 纸白底、深墨文字、灰绿主操作；衬线标题与等宽编号；2px 组件圆角 | 审批、复核与审计阅读 | 单份申请阅读最集中；批量扫描列表时需要更多纵向空间 |
| C 石墨 · 运行控制台 | 窄图标导航；紧凑操作队列；固定详情区；附最近事件记录 | 石墨底、低饱和浅绿主操作；等宽标识与紧凑表格；3px 组件圆角 | 频繁切换记录、运维核对与异常处理 | 同屏信息多；只用图标的导航对新用户需要更明确的提示与后续验证 |

建议优先考虑 A：MCPGuard 后续将管理多套资源、用户账号、权限、私有交付和审计，稳定的全局导航和资源表格更便于扩展。若主要使用者是审批人员，B 的案卷结构值得优先考虑；C 更适合运维场景。这个建议不等于已选择方案。

## 预览覆盖

三种方向均提供：操作与审批、资源目录、策略规则、用户与权限、本人审计、通知与设置、组件与状态。

可以实际操作的预览内容：

- 切换视觉方向与场景；链接参数 `concept=a|b|c`、`view=actions|resources|rules|users|audit|settings|components` 可直接定位。
- 在 A/C 的操作表格内搜索和筛选，选择不同记录查看详情。B 通过案卷目录审阅记录。
- 切换资源查看访问范围与流程；资源申请按钮展示流程说明。
- 点击身份切换为 Alice 的样例视角，检查本人申请不能自行审批。
- 打开审批/拒绝确认，使用 Escape 关闭，关闭后焦点回到触发控件。
- 查看等待审批、已批准待恢复、结果待核对、已完成的不同语义；未知结果不提供重试或重做按钮。
- 查看按钮默认、禁用、加载，表单错误、空状态与加载反馈；检查键盘焦点、窄屏和减少动画设置。

## 业务与证据边界

全部内容均为固定设计样例。页面无 `fetch`、WebSocket、MCP 客户端或业务 API 连接；不会读取凭据、保存审批、创建账号、申请权限、执行 SQL、发送通知或吊销权限。

资源目录、账号及权限、凭据交付和激活的展示用于验证新设计能否容纳既定多资源流程，不能作为当前生产页面已接入这些功能的证据。正式接线须以已实现的版本化契约和后续 UI 开发范围为准。

现有业务页面、后端、版本化契约、历史验证记录在本次方案准备中保持原有字节。完整的改前文件 SHA-256 基线保存于 `.dev/ui-redesign-2026-10-29/baseline.json`；新增的方案和验证证据单独存放，不覆写旧验收。

## 方向确定后的实施顺序

1. 根据选定方向建立项目权威 `design-system/mcpguard/MASTER.md`，确定语义颜色、中文字体、字号、间距、圆角、尺寸与动效；本草案尚不充当已批准规范。
2. 将 token 编码为两套前端共用的样式源，定义按钮、输入、表格、状态、确认框、空状态及加载反馈的组件约束。
3. 优先迁移当前网关内嵌控制台的全部现有场景，保留登录、角色、对象鉴权、CSRF、配置版本、幂等、审批和未知结果的规则。
4. `web/` 下 Vue 早期原型明确保留其历史/演示身份。统一基础主题时不将静态数据或占位按钮宣称为已接入真实业务，也不擅自替换当前控制台。
5. 完成构建、适当回归、实际浏览器检查和界面截图，另行记录技术验证与用户视觉验收。业务功能增加以原开发计划为准。

## 本次本地检查

已使用本地 Chrome 对离线文件完成 **348 项检查**。三种方案、七个场景、1600/1024/768/375px 四种宽度共 84 个组合均能显示主标题与导航，页面本身无横向溢出；宽表格在独立区域内滚动。

额外检查包含搜索与筛选、空状态、申请详情、审批/拒绝确认、Escape 关闭与焦点恢复、本人不能自批、未知结果无重放按钮、两种样例身份的资源权限不混用、减少动画，以及单文件交付可直接渲染和操作。27 组候选语义颜色的文字对比度均至少为 4.5:1。此为所列检查的技术结果，不宣称完整无障碍认证或用户视觉验收。

保留 12 张当前方案截图；浏览器 JavaScript 异常为 0，预览目录以外的请求为 0。与改前 SHA-256 基线对比，401 个既有非忽略文件均保持原有字节，包括业务源码、契约、数据库迁移和历史验收记录。改前页面与后端没有重新构建或发布。

检查期间发现的手机端溢出、辅助文字对比度问题均已修复后复核。失败日志留在 `.dev/ui-redesign-2026-10-29/`，未将失败过程改写成通过；本机 HTTP/内置浏览器入口未成功，正式交付采用已经检查过的离线文件。

## 实现文件

- `index.html`：方向选择入口、样例说明和审批确认框。
- `styles.css`：三种方向各自的候选主题变量、组件样式、独立布局与响应式规则。
- `preview.js`：固定样例和纯本地预览交互。

- `source-manifest.json`：预览源码和单文件交付的 SHA-256。
- `verification.json`、`screenshots/`：本次检查结果与截图；不替代用户选择和视觉验收。
