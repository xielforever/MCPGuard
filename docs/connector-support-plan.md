## 需求来源与现状

- 用户已确定由执契提供企业应用连接，后端按 App 实例配置。客户端可走标准 MCP，也可用后续的 DSH 原生入口。两条入口使用同一网关核验身份、授权、审批、执行与审计。
- 2026-11-25 核对远端 `main` 为 `b1bc240`。Wave 4 的 [#29](https://github.com/xielforever/MCPGuard/issues/29) 为 Open，验收范围是原四类连接器的控制台管理和限域读取。[双项目证据](validation/local-connector-multi-project-2026-11-21.md) 已核对共享、私有和停用场景。本地品牌工作树承载本草案。
- [Jenkins App 隔离验收](validation/local-jenkins-app-2026-11-22.md) 已覆盖 Chrome 创建、测试和启用同一 App，以及安装版 DSH 经 Streamable HTTP 使用该 App 完成动态参数查询、独立审批、队列回执及故障验证。此次以该记录为基线，验收从页面配置到本次 DSH 连接器交付的完整链路。
- [MySQL App](validation/local-mysql-app-2026-11-22.md) 已完成隔离验证。[18080 本机证据](validation/local-mysql-app-18080-2026-11-23.md) 中单库只读与停用通过，第二身份因令牌返回 HTTP 401 未取得本机 App 授权拒绝证据。
- 本机安装包读回 DSH MCP 管理器版本为 `0.2.2-rc.5`。[官方 MCP 管理器](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-manager/README.md) 提供现成的 MCP 注册与连接管理做法。实际插件接口和凭据引用以选定安装版验证。

| 已有 App | 当前操作与范围 |
| --- | --- |
| Jenkins | 限定文件夹内查任务、查动态参数。显式启用受控构建的 App 可提交审批和查询队列。 |
| Kubernetes | 读取明确登记的单一命名空间内的 Deployment 摘要。 |
| PostgreSQL | App 工具读取授权 Schema 的表目录。已有资源级受控写沿用其授权及通知流程。 |
| MySQL | 单库内读取基表目录及字段结构。 |
| Redis | 读取指定键前缀内的单个键。 |

## 确认范围

| 字段 | 记录 |
| --- | --- |
| 计划状态与确认记录 | 草案。用户于 2026-11-25 明确要求首批 Must 能在页面配置 Jenkins 连接器，再通过 DSH 操作执契连接器。 |
| 已确认的约束 | 执契提供统一 MCP 接入。App 权限按主体和后端范围核验，已有工具名和传输继续兼容。Kubernetes 延续指定命名空间的只读边界。 |
| 首批使用场景 | 管理员在「资源 → 连接器」登记 Jenkins 地址、任务文件夹及专用凭据，选定调用主体，开启「允许提交构建审批」，测试通过后启用。开发者在 DSH 经执契发现该 App，按实时参数提交构建，在独立审批后用原动作继续并查询队列。 |
| 实施方案 | 沿用上一版建议的可安装 DSH 入口，由 DSH 连接执契并使用自己的调用身份。Jenkins 凭据由执契保存。标准 MCP 客户端读取同一 App，用于验证兼容性和权限一致性。 |
| 构建前置条件 | 隔离环境已开启连接器管理，组织已配置 Jenkins 受控资源，申请人具备构建提交权限，审批人具有独立审批权限。App 的获准调用主体在页面选择。[现有配置说明](jenkins-integration.md) |
| 审批与渠道边界 | Jenkins 沿用独立审批、原申请人显式继续。[PostgreSQL 高危操作](validation/local-wave2-high-risk-2026-11-21.md) 沿用已有的渠道通知、短时授权码和审计。 |
| Issue 和波次 | [#29](https://github.com/xielforever/MCPGuard/issues/29) 的页面管理范围和已归档 Jenkins App 是基线。首批新增的交付验收在计划定稿后按仓库规则查重并承接对应工作项。[#21](https://github.com/xielforever/MCPGuard/issues/21) 按既有 RA-18 范围继续 Review。 |

## 优先级

| 档位 | 事项 | 取舍理由 | 工时与依赖 |
| --- | --- | --- | --- |
| M | 在执契页面配置 Jenkins App，并由 DSH 通过执契完成同一个 App 的受控构建 | 最低验收覆盖页面配置到队列回执的完整链路。缺少页面配置，管理员无法自助接入。缺少 DSH 实测，无法确认页面登记的 App 可被获准身份直接操作。文件预置只能验证旧接入，底层 API 测试只能覆盖网关契约。 | 无。目标 DSH 安装版、具备两种参数定义的隔离 Jenkins、配置管理员、获准申请人和独立审批人。 |
| S · 建议 | Kubernetes 排障，延伸到 Pod 状态、重启次数与相关事件 | 在指定命名空间内用上述数据定位一次镜像拉取失败，跨命名空间请求被拒。顺延期间可先查 Deployment，由获准运维人员补查 Pod 与事件。 | 无。隔离集群、明确命名空间及只读服务账号。 |
| C | 华为云或腾讯云的一项只读资产发现 | 从 ECS 或 CVM 实例清单选一个场景，按获准地域及项目读取实例状态。 | 无。可用的测试云账号及实际资源范围。 |
| C | 将一个外部 MCP 服务登记为上游 App | 有实际使用场景后评估工具发现和选定工具的授权发布。 | 无。可用的上游服务、身份及允许调用的工具范围。 |
| C | 企业身份与 SSO | 有对接需求时复评身份映射及生命周期。 | 无。身份源、对接人及测试账号。 |
| 建议 W | 生产部署及正式环境验收 | 当前结果可在隔离环境交付。获批范围、候选版本与回退准备齐备后，进入 [#24](https://github.com/xielforever/MCPGuard/issues/24) 和 [#25](https://github.com/xielforever/MCPGuard/issues/25) 所属发布流程。 | 无。生产范围与窗口由该波次确认。 |

## 验收条件

验收从控制台新建 App 开始。页面、DSH、网关和 Jenkins 四处的证据通过同一个 `connectorId` 及各笔构建的 `actionId` 核对。

| 验收编号 | 可观察的完成条件 | 计划验证 |
| --- | --- | --- |
| 验收 6 | 管理员在执契「资源 → 连接器」新建 Jenkins App，填写名称、控制器地址、任务文件夹和专用凭据，选择调用主体并开启构建审批。连通测试通过后可启用，测试失败的草稿无法启用。 | 在仅启用控制台连接器配置的隔离实例用浏览器操作，记录新 App 的 `connectorId`、连通测试、授权及启用状态。确认页面详情只显示凭据安全摘要。 |
| 验收 1 | 从干净的 DSH 隔离配置安装执契连接器。设置执契网关和该用户的调用身份后，DSH 能发现页面新建并授权的 Jenkins App，重启后可继续使用。插件展示名为「执契连接器」，使用白文篆印。 | 记录 DSH 版本、插件版本、安装和重启结果。对照页面和 DSH 的 `connectorId`。检查 DSH 工具结果只含获准配置和业务数据，Jenkins 凭据保存在网关。 |
| 验收 2 | 在 DSH 用页面新建的同一 `connectorId` 列出获准文件夹内的任务，读取两个参数不同的任务。提交后显示待审批，独立审批人在执契页面批准后，申请人在 DSH 用原 `actionId` 继续并读到 Jenkins 队列回执。 | 复用现有 Jenkins 隔离夹具，对照实时参数、待批时零派发、批准身份、队列编号及实际构建。以同一 App 的任务范围核对列表和查询结果。 |
| 验收 3 | 两个独立身份按授权看到共享和私有 App。未授权调用和超出配置文件夹的任务调用被拒。管理员从页面停用 App 后，已有会话的下一次调用被拒。标准 MCP 客户端和 DSH 连接器均受同一网关授权约束。 | 用两个合法身份分别核对目录和直接调用。管理员从页面停用 App 后，两边重试同一查询并核对 Jenkins 调用计数。 |
| 验收 4 | 审批期间参数变化会拦截旧计划。重复提交、重复继续或回执丢失均不产生第二次 Jenkins 构建。DSH 显示服务端返回的已保存结果或未知状态。 | 执行参数漂移与故障夹具。使用原动作编号查询链路，核对实际 Jenkins 队列计数。 |
| 验收 5 | 可沿同一 App 对照页面登记、测试、授权和启停，并按动作编号对照请求、独立审批、派发和结果。旧 HTTP/stdio 与现有文件配置通过回归。 | 固定候选提交与验证版本，归档脱敏页面、DSH、网关审计和 Jenkins 证据。按照项目完成条件从远端读回对应记录。 |
