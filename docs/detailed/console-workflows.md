# 控制台页面与操作流程设计

版本：v0.1 设计补充。日期：2026-10-22。本文定义页面、交互和文案，尚未实现页面或取得产品验收结果。受权状态形状见[ActionView Schema](../specs/action-view.schema.json)，控制工具结果见[ActionControlResult](../specs/action-control-result.schema.json)。

控制台帮助员工看清请求、帮助合格他人决定、帮助运维核对真实结果。首版保持已确认规则：授权普通读取自动执行，受控写由他人审批，高危默认禁止，全部操作来自受控工具目录。

页面依赖[管理API](service-operations.md)、[权限策略](security-policy.md)与[状态模型](state-storage.md)。ChatGPT接入、账户与平台能力边界见[首发方案](chatgpt-access.md)；本稿不重新选择IdP、通知平台或账号类型。

## 1 导航、路由与角色

以下为拟议前端路由，不是新增API路径。导航是否显示、对象能否访问及按钮能否执行均以服务端当次授权为准，前端隐藏按钮不能代替鉴权。

| 导航 / 路由 | 面向用户 | 页面目标 |
|---|---|---|
| 我的请求 /requests | 员工及兼任角色 | 查看本人受权请求、决定、执行和结果 |
| 请求详情 /requests/:id | 本人或明确受权人员 | 确认固定计划、当前阶段与下一步 |
| 待我处理 /approvals | 合格审批人 | 只显示其当前资格范围内的请求 |
| 审批详情 /approvals/:id | 合格审批人 | 查看足够决策的受权详情并批准/拒绝 |
| 资源 /resources | 资源管理员或受权查看人 | 管理服务归属、受控连接与版本 |
| 工具 /tools | 工具发布人 | 查看Schema、原生操作、限制和发布状态 |
| 策略 /policies | 策略管理员 | 审核规则差异及其影响 |
| 执行核对 /executions | 明确运维/核对权限人员 | 处理结果未知与原生证据 |
| 审计 /audit | 审计员及受权人员 | 检索关联事实与受控导出 |

审批人的权限不等于业务数据读取权。Alice可在scope A发起操作，Bob可获准审批指定scope A计划，但不会因此获得该范围的业务调用或完整结果读取权。

首版审批ID映射Action ID，链接打开后仍需企业登录及对象鉴权。链接本身、邮件转发、ChatGPT文本或知道ID均不授予访问权。

## 2 列表与详情的基础内容

我的请求列表显示发起时间、工具名称、受权资源名称、操作摘要、业务阶段、执行结果、到期时间和详情入口。列表不显示完整参数、凭据、认证头或大块结果；筛选项包括时间、工具、资源与状态。

详情顶部保持固定结构：当前阶段及明确文案、可用操作、发起人与时间、请求ID。下方分为操作计划、审批记录、执行结果、时间线；空内容明确标记“尚未发生”，不能用静态成功样本填充。

| 详情区域 | 最小内容与展示约束 |
|---|---|
| 操作计划 | 工具及版本、真实目标、操作语义、完整受权参数、范围、前置条件、影响/结果上限、到期时间 |
| 身份 | 发起人、可公开的实际后端身份、审批人；均不展示密码或令牌 |
| 审批记录 | 批准/拒绝、可信决策人、时间、理由、计划版本；保留历史 |
| 执行结果 | 是否已派发、请求结果、已知副作用、脱敏业务结果、截断/过期提示 |
| 时间线 | 创建、待批、决定、领取、原生证据、结果和取消/核对事件 |
| 技术关联 | 请求、尝试和执行ID，仅在受权详情展开，不占据主要操作流程 |

审批摘要便于扫描，不能代替完整计划。审批者应能查看其有权看到且足以判断操作的完整细节；无法取得必要细节时显示原因并禁用批准，不能让“参数已隐藏”变成盲批入口。

参数展示保留类型、空值、数量和二进制编码说明。长列表有界折叠与检索，不能仅显示前三项就使剩余目标不受审阅；完整列表与摘要必须绑定同一固定计划。

## 3 业务状态与副作用分别显示

主状态条表达Action阶段，执行区表达副作用。不能仅凭绿色HTTP响应、审批按钮成功、错误或取消推断后端是否生效。

| Action状态 | 用户文案 | 下一步与按钮约束 |
|---|---|---|
| PENDING_APPROVAL | 等待合格他人审批，尚未执行 | 员工可查看或按权限取消；合格他人可批准/拒绝 |
| READY，来源HUMAN | 已批准，尚未执行 | CONTROL_FLOW显示继续指引；不显示“执行成功” |
| READY，来源POLICY | 已通过策略，等待执行 | 正常自动读取路径可快速经过；不伪造人工批准记录 |
| EXECUTING | 正在处理，请勿重复提交 | 可查询；有权时请求取消，不声称一定停止 |
| SUCCEEDED | 操作成功 | 展示真实结果与副作用证据，允许受控查询 |
| FAILED | 操作未成功，请查看影响说明 | 必须同时展示NONE/ROLLED_BACK/PARTIAL/APPLIED/UNKNOWN实际状态 |
| DENIED | 已拒绝，未获得执行资格 | 区分策略阻止与他人拒绝；不提供继续执行 |
| CANCELLED | 请求已取消 | 是否发生过派发和副作用另列，不能统一写“已撤销变更” |
| EXPIRED | 请求已过期，不能继续 | 新操作需重新发起和评估，不复活原请求 |
| OUTCOME_UNKNOWN | 无法确认最终结果，请先核对 | 展示核对入口或联系受权人员，不提供一键重试 |

副作用文案固定为“无业务变更”“已生效”“确认已回滚”“部分生效”“影响未知”。只有可靠证据支持时才显示前四项；原生结果格式校验失败也可能已经生效。

未领取执行权时执行ID为空，展示“尚未派发”；有执行记录但尚无发送证据时展示“已进入执行处理，尚无派发确认”。不把记录存在显示为“后端已收到”。

## 4 ChatGPT受控写的完整操作

1. Alice在ChatGPT请求目录内的受控写，网关校验scope与操作后创建固定计划。
2. ChatGPT收到待批结果与门户链接，文案为“请求已提交，尚未执行；请由合格他人审批”。
3. Alice打开我的请求看到PENDING_APPROVAL，可查看计划和取消；不能审批自己的请求。
4. Bob打开待我处理，经企业登录查看真实目标、完整受权计划、限制与到期时间，再批准或拒绝。
5. 批准只记录决定。Bob看到“已批准，等待操作人继续”，Alice看到“已批准，尚未执行”。
6. Alice返回ChatGPT明确要求查询该请求，并在获批后继续；使用新的action.status/action.resume调用。
7. 网关重新校验原计划、当前身份/权限及期限后领取原Action资格，再执行原生操作。
8. Alice在ChatGPT或门户查看实际结果；重复查询和重复resume不会产生第二次派发。

门户提供“复制继续指引”，内容仅含请求ID与自然语言步骤，例如“查询请求［ID］；若已获批且仍有效，继续该请求”。复制内容不含批准令牌、完整敏感参数或重新生成的SQL。

门户首版不新增浏览器“执行”按钮或管理REST续传路径；后台批准、通知到达和页面刷新也不触发执行。ChatGPT不会被假定自动轮询或自动后台继续。

ChatGPT自身的操作确认仍可能出现，平台也可能阻断某动作；该确认不能替代Bob的企业审批。平台尚未发出请求时，门户不能虚构对应Attempt或网关成功记录。

普通有界等待与MRTR使用相同计划/决定/执行区，但下一步提示遵循其实际交互模式；不能把已结束的普通等待请求临时改成CONTROL_FLOW。

## 5 审批详情与操作确认

审批页头部显示“你正在为他人决定”，并展示操作人、工具、资源、具体变更、影响限制和到期时间。清晰区分预览观察时点与执行前置条件，不把预览数量当成最终保证。

| 条件 | 批准按钮 | 页面反馈 |
|---|---|---|
| 合格他人、当前计划有效、尚未领取且服务端允许 | 可用 | 批准决定绑定页面当前计划与版本 |
| 审批者就是操作人 | 禁用或不出现 | 本请求须由其他合格人员审批 |
| 已撤销审批资格或无对象访问权 | 不可用 | 你当前无权处理此请求 |
| 计划已失效、依赖配置已变、过期、取消或被拒绝 | 不可用 | 当前请求不能继续；请查看最新状态 |
| 无权查看足以决策的细节 | 不可用 | 无法查看必要操作详情，不能批准 |
| 已领取或已完成 | 不可用 | 操作已进入执行/已结束，不能追加批准改变事实 |

批准确认层再次给出操作人、目标、关键变更和期限，按钮明确为“批准此计划”；拒绝提交明确理由。确认层不再次输入命令，也不允许编辑请求参数后批准。

页面用当前版本条件与幂等键提交决定，服务端最终核验资格。按钮禁用、倒计时和浏览器中展示的姓名只是交互辅助，不作为可信决定来源。

已批准但尚未领取时，只有服务端明确允许且当前人员仍合格，才显示“拒绝继续”等后续决定；这是追加决定，不删除原批准。页面不得自造撤销接口或保证能召回已派发操作。

## 6 并发、断线与过期反馈

同一管理员或审批人打开多个页面时，任何写操作都携带读取版本；同一次提交及其网络重试复用同一Idempotency-Key。改变内容后创建新命令，不复用旧键。

| 事件 | 页面处理 |
|---|---|
| 双击或提交后短时重试 | 禁用重复按钮并查询同一命令，沿用同键；不创建第二个决定 |
| 412版本冲突 | “内容已更新，请重新查看后决定”；重新加载计划和状态，不自动覆盖提交 |
| 428缺少版本条件 | 明确提交失败并刷新对象；作为客户端缺陷记录，不去掉条件重发 |
| 409幂等键异体或状态冲突 | 展示冲突原因和最新状态，不静默改用新键重做 |
| 发送后断线、结果未知 | 显示“正在核实提交结果”；先查状态或同键重放，不能显示已批准 |
| 命令去重有效期已过 | 停止自动重放，核查实际决定和状态后再处理 |
| 页面倒计时到零 | 暂停提交并刷新；到期事实由服务端判定，不仅信任本机时钟 |

批准与取消、过期、撤权同时发生时，以服务端提交结果为准。失败页面保留用户输入的非敏感理由以便理解，但不自动把它提交到新计划。

列表返回有界游标分页；状态更新后旧游标失效则重新查询，不拼接不同版本结果。刷新频率有上限，切后台时降频；敏感详情不被不受控浏览器持久缓存。

## 7 取消与错误反馈

派发前取消成功可展示“已取消，未派发”。派发后返回202只展示“取消请求已受理，正在确认结果”，继续显示原执行事实，不马上跳转“变更已撤销”。

员工取消后仍可在其当前受权范围内查询；已失去访问权时按服务端反馈处理，不能因“这是我以前的请求”继续显示受限结果。管理员介入也须有明确对象权限。

网关401提示登录失效并保留受保护的返回路径，重新登录后重新读取对象；403提示无权限，不尝试切共享管理员身份。原生服务401、数据库认证或Redis认证失败显示在执行区，文案如“目标服务认证失败，操作结果见影响说明”，不要求员工反复登录ChatGPT。

任何错误中的原生地址、连接串、认证头与堆栈都先脱敏。可复制受控请求ID用于定位，不提供“复制完整原始异常”泄漏入口。

## 8 资源、工具与策略管理

资源页显示类型、归属、可访问范围、启用状态、版本和最近受控连通检查。凭据仅展示引用/版本及状态，不提供明文读取；测试连接只针对已注册配置，不能输入临时任意目标。

工具页分离候选版本与当前发布版本，展示输入/输出Schema、绑定资源、原生操作、读写语义、限制和策略引用。首版不出现任意SQL、任意Redis命令或任意URL调用面板。

发布前给出具体差异、受影响工具/资源、旧未执行计划可能失效的提示及验证结果；明确显示“网关已发布”和“ChatGPT快照已刷新/待刷新”两个状态。

ChatGPT共享目录不能被展示成逐用户实时工具隐藏。工具元信息严格隔离时按权限组应用发布并验证；平台仍可显示旧工具时，当前资源与数据权限依然决定调用结果。

策略页按确定规则显示允许、需他人审批和拒绝的组合理由。风险、数据范围与影响上限来自受控配置，不能在调用详情中临时点击“降低风险”绕过禁止或他人审批。

资源停启、策略或凭据版本变化提交后，页面刷新相关计划状态。失效的计划通过新Action重新评估，不在原请求上悄悄替换目标、参数或身份。

## 9 结果未知的核对工作台

未知执行页突出“请勿重复提交”，展示请求ID、目标、固定计划、已知派发/原生证据、可能影响和最后更新时间。只有明确核对权限者可发起只读核对；普通员工看到可联系人员或受控状态。

核对操作只查询可信回执或业务状态，展示证据来源、观察时点、能证明什么及仍未知的部分。当前值相同不足以证明某次写已执行，人工备注不覆盖原始派发事实。

页面没有一键重试、重新领取或“标记未执行并重做”。后续确需重做时由受权人员先处理原不确定性，再发起独立新意图、展示旧风险并重新授权；不从核对按钮直接执行原命令。

## 10 审计、可访问性与验收

审计页按时间、操作人、工具、资源和Action检索，关联决定及执行；导出需独立权限且文件访问再次鉴权。审计员不自动拥有全部参数、业务结果或凭据读取权。

状态同时提供文本和图标，不仅用颜色；键盘可完成筛选、展开详情与确认，焦点返回触发控件。大JSON按文本安全显示，长标识可复制，窄屏保留目标、关键变更和决定按钮的阅读顺序。

验收使用Alice操作者、Bob合格他人及无权限用户，覆盖ChatGPT待批/继续、禁止自批、决定不派发、412/409、取消202、未知不重放、旧快照和敏感详情保护，关联[验证计划](validation-plan.md)的AC-01至AC-13与V02/V03/V05/V08/V10–V14/V19/V21。

本文件未宣称ChatGPT账号能力、真实IdP、通知平台或页面已接通。后续页面验收须同时核对用户所见文案、真实持久状态与后端效果。
