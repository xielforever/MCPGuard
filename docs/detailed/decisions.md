# 设计决策与待确认事项

版本：v0.1 详细设计。日期：2026-10-22。

架构边界沿用已确认需求。本轮依据工程实践选定实现基线，并把企业业务选择单独保留为待确认项。设计选择可以在评审中调整，均未表示功能已经实现。

## 1 已确认的产品约束

企业集中、多人多资源；MCP Server 就是企业网关；HTTP MCP 直连与 stdio 转 HTTP 两入口均交付；网关原生访问 PG、Redis、HTTP API；资源混合部署且网络已通。以上不再重新询问。

## 2 本轮工程决策

| ID | 设计基线 | 选择理由与代价 |
|---|---|---|
| E-01 | 模块化 Go 单服务，加独立 mcpguard-connect；Vue 控制台 | 统一策略与调用链，减少分布式事务和部署负担；以后按实际瓶颈拆分 |
| E-02 | PostgreSQL 作为唯一权威元数据与授权状态库 | 事务、行锁、唯一约束支撑持久审批与单次领取；不沿用内存/SQLite承担企业权威状态 |
| E-03 | 官方 Go MCP SDK 固定版本并满足其工具链要求 | 协议解析与 transport 交给 SDK，领域授权/执行自建；SDK 支持不等于 IDE 组合通过 |
| E-04 | RBAC 加资源属性/数据范围；基础准入后做风险策略 | 默认拒绝，DENY优先，规则结果确定且可解释；审批不扩展访问权 |
| E-05 | 一个 Action 固定一个不可变计划 | 参数或相关语义改变就创建新 Action 并重新评估，降低批准后替换目标风险 |
| E-06 | 领取与意图同库事务，Execution按Action唯一 | 消费资格后不自动恢复；降低重复写入风险，但未知窗口需核对而非保证自动恢复 |
| E-07 | Outbox仅用于通知与状态事件 | 至少一次投递可去重，不把原生写操作放入通用重试队列；首版无需Kafka等依赖 |
| E-08 | 三种明确交互：有界等待、显式控制工具、MRTR | 支持常见tools-only客户端并适配已验证新能力；不依赖Tasks或IDE私有插件 |
| E-09 | 凭据引用、加密参数/结果、系统凭据库 | IDE只持网关访问令牌；具体密钥产品按企业现状适配 |
| E-10 | 无副作用准备、短原生事务、未知写不自动重放 | 审批不占用连接或锁；PG/Redis/HTTP各自表达实际副作用，牺牲部分自动恢复能力换取可解释性 |
| E-11 | 管理命令版本前提与幂等 | If-Match防覆盖，Idempotency-Key防重复命令；不能推导后端业务写幂等 |
| E-12 | 本地授权epoch串行边界与持久CAS | 本地撤权与领取按提交顺序生效；外部身份传播与远端发包仍有明确窗口 |

这些是本轮选用的工程方案，供实施与评审；它们不是“用户已确认”的业务规则。技术版本/镜像在实现时固定到维护中的补丁，不把最低兼容版本当永久生产版本。

## 3 用户决定与仍待补充的信息

2026-10-22用户已答复：风险分级、受控工具目录、首发ChatGPT。具体工具示例不因此成为已批准生产操作，账号/工作区、企业身份源和通知平台尚需落实。

| ID / 关联项 | 状态 | 已决定或剩余信息 | 设计处理 |
|---|---|---|---|
| Q-01 / D-01、D-06 | 已确认基线 | 授权普通读取自动、受控写他人审批、高危默认禁；敏感读细分类与审批组待细化 | 按此实现规则与禁止自批；ChatGPT自己的确认不替代企业决定 |
| Q-02 / D-03 | 已确认形态 | 受控PG模板、限定Redis命令/key、已登记API operation；六个示例工具仍是候选 | v0.1不开放通用SQL/Redis入口或任意URL，具体名单与数据范围再细化 |
| Q-03 / D-02、D-04、D-06 | 部分确认 | 首发ChatGPT；账号/工作区及具体界面待核实，企业IdP与通知平台未提供 | 先完善远程HTTP方案与模拟集成；stdio另选真实支持客户端，保留整体交付目标 |

工程上首版采用单级他人决策；多人会签、代理审批、紧急授权等不作为默认能力。未来若需要通用SQL/命令，单列解析、范围、权限与故障验收设计，不以确认按钮替代约束。
ChatGPT账号/工作区已单独询问，尚未回答时不猜测其写工具或应用管理权限；平台实际能力可能限制客户端侧读写验收，网关的企业授权与执行约束保持一致。

2026-10-22 后续用户决定：首轮采用 HTTPS + Streamable HTTP 远程直连，补齐 OAuth 与临时 HTTPS 入口，保留现有本地测试模式，再进行 ChatGPT 真实读取。实现采用显式 `oauth-fixture`、预注册客户端和隔离 PG 夹具；这是模拟身份授权联调，不表示企业 IdP 已选择或生产 SSO 已完成。Quick Tunnel 首轮仅验证 Streamable HTTP JSON POST；SSE、持续通知和企业写流程另验。具体启动与关闭步骤见[接入说明](../oauth-local-chatgpt.md)。

## 4 无需现在阻塞的部署参数

| 项目 | 工程处理 | 最迟落实 |
|---|---|---|

| 副本与可用性 | 第一条闭环可单实例，权威约束从首版起跨实例成立；会话/流另验 | 多副本发布前 |
| 结果和审计保留期 | 分类保留、加密、清理墓碑和受控查询；不提前清理待执行计划 | 数据进入真实留存周期前 |
| 外部组同步/撤权时效 | 定义源、同步机制、新鲜度预算和失联行为，超预算高风险不派发 | 真实身份接入前 |
| 灾难恢复 | 恢复后默认关闭写派发，核对恢复点之后的效果 | 首次生产写入前 |

## 5 决策变更规则

决定记录包含来源、日期、选项、理由、影响的工具/权限/协议组合及验收。用户回答Q项后更新本页、相应详细设计、[需求](../requirements.md)与[交付计划](../delivery-plan.md)，不只在聊天中接受。

改变计划语义或执行身份时，旧Action和批准不能自动迁移；修改版本需使受影响的未领取计划重验或失效。已派发记录保持历史事实，不因策略更新改写结果。
