# 故障处置与恢复手册

版本：v0.1 详细设计。日期：2026-10-22。状态：拟议运行规程，尚未实现或演练。
依据：[状态与存储](state-storage.md)、[原生执行](native-execution.md)、[服务运行](service-operations.md)及[ChatGPT接入](chatgpt-access.md)。

本手册处理网关、原生服务和平台故障后的可确认事实。处置目标是阻止扩大影响、保存证据，再按资源恢复；同一Action的执行资格不会因值班操作、租约到期或重启重新产生。

## 1 角色、冻结范围与事件记录

值班人员负责隔离和证据收集，资源负责人核对原生业务事实，身份/密钥管理员处理撤权与凭据，授权人员按权限决定新操作。拥有运维角色不自动获得业务数据、审批或任意修改执行结果的权限。

写门禁应覆盖所有实例上的业务写工具、action.resume及可派发的MRTR续传；仅关闭某个HTTP入口或某台实例readiness，不保证其他入口与已领取执行停止。现有查询和审批决定仍按当前权限处理，不能把冻结显示为已经取消或回滚。

| 记录 | 最少内容 |
|---|---|
| 事件关联 | incidentId、资源、Action/Attempt/Execution、计划与凭据版本、实例启动代际 |
| 时间线 | 最后健康时间、领取提交、已知发送/响应、告警、隔离与恢复决定 |
| 原生证据 | 操作回执、事务/业务版本、实际效果；请求收到次数与生效次数分列 |
| 处置证据 | 谁在何时做了何种受权操作、证据来源、仍不能确认的部分 |
| 恢复范围 | 哪些实例/资源已核验、哪些继续冻结、何人授权开放 |

不把密码、token、确认秘密或完整敏感参数复制到事件工单；完整详情通过受控引用访问。时间线采用明确时区，不能只靠来自不同机器的日志先后顺序推导提交顺序。

## 2 原生写入结果未知

进入条件：请求超时、断线、进程丢失或结果落库失败，不能确认已批准写入的最终效果。由值班人员与资源负责人共同处理。

1. 定位原Action及Execution，保留计划、派发意图、已知证据与当前副作用状态；不删除或重置资格记录。
2. 阻止对该Action重派，并按影响范围冻结相关资源或业务对象的新写入，避免人工核对期间再次改变目标。
3. 区分DISPATCHED与DISPATCH_UNKNOWN：前者有发送证据，后者连是否发出都不确定；两者均不能据错误响应认定未生效。
4. 检查原执行者是否仍存活、是否可能恢复发送；必要隔离见第6节，不能以租约到期代替隔离确认。
5. 仅通过已注册的只读Reconcile查询可信回执或可唯一关联该Execution的业务证据，记录观察来源与时点。
6. 证据足够时由领域服务追加核对结果，保留原始时间线；证据不足则保持OUTCOME_UNKNOWN及相应副作用状态。
7. 操作人需要重做时创建新Action，展示旧操作不确定性并重新授权；不得把重做伪装成原Action的安全续传。

PG当前行、Redis当前值或HTTP当前资源恰好等于期望值，通常不足以证明某次执行已完成。也不能以“当前值没变化”排除曾生效后又被其他调用修改。

恢复门槛：原执行者已受控；可靠证据能够解释效果，或未明范围保持冻结并有明确处理责任。允许其他无关资源恢复，不因服务恢复可达就批量重放未知操作。

必须保留：原生回执/业务版本、查询身份与模板、查询时点、判断理由、状态前后快照。手工备注不能单独把未知写标为成功、回滚或未执行。

## 3 元数据库不可用或提交结果不明

进入条件：PostgreSQL连接、锁/事务预算、迁移兼容性或必要审计持久化异常。值班人员先保护领取与状态事实，再处理数据库。

1. 将不满足条件的实例readiness置为不可接收新受控请求，停止新执行领取；不能使用旧权限缓存继续派发。
2. 对已领取但能确定尚未发出的路径停止发送；在途原生调用尽力取消，保留可取得证据，不声称副作用撤销。
3. 无法保存结果时记录受保护的故障关联与告警；临时日志不替代权威授权/执行记录，也不据此补发原生操作。
4. 核对数据库服务、连接池与锁等待、迁移版本和事务失败原因；诊断访问只读或使用专门受权的数据库运维身份。
5. COMMIT返回不明时按原command/Action/Execution标识查询既有记录，不能简单重跑整个“领取—原生执行—落库”函数。
6. 数据库恢复后先核对意图、未完成命令和未知执行，再开放新领取；未能确认的记录继续按第2节处理。

本地事务死锁/序列化重试只能覆盖确定没有跨原生派发的数据库事务。一次元数据查询成功不证明所有实例、待批状态和执行者均已恢复。

恢复门槛：迁移兼容、必要读写事务和审计可用、故障期间领取意图已分类；若发生数据回退，必须走第8节，不能当普通连接恢复处理。

## 4 通知失败、重复或乱序

进入条件：outbox积压、通知平台超时/业务失败、送达回执丢失、重复按钮事件。通知负责人和值班人员共同检查。

1. 区分“通知未送达”“审批尚未决定”和“已决定但调用未继续”，按Action真实状态展示，不以IM文本判断批准。
2. 检查事件类型、dedupe key、投递次数、可再次投递时间和受控诊断；不在普通日志打印授权秘密或完整参数。
3. 通知worker仅领取通知事件，发送后按claim token确认；超时可按退避重投，同一事件保持稳定标识。
4. 重复或乱序决定仍验证实际人类身份、资格、计划摘要及有效期；同来源事件不同内容按冲突处理。
5. 普通等待已结束、Action已取消/到期或资格已消费时，迟到通知与决定不能恢复执行权。
6. 人类可在受权门户处理现有请求；通知恢复后只补送仍有意义的状态，不自动批准或启动原生执行。

通知投递为至少一次，重复送达不是重复业务写的许可。Outbox不能混入PG写、Redis命令或业务HTTP重试任务。

恢复门槛：平台业务响应与送达行为核实、积压已分类、重复决定不改变终态；必要事件可在有效期限内送达。保留事件ID、业务响应、去重/冲突及Action最终状态证据。

## 5 凭据轮换失败或疑似泄漏

进入条件：后端认证异常、新旧凭据混用、秘密疑似暴露。密钥管理员与资源负责人负责，值班人员控制派发。

1. 按影响范围停用资源或凭据绑定，提交本地授权版本变化并阻止后续领取；紧急收缩权限不等待新的业务批准。
2. 对疑似泄漏凭据在实际后端/托管方撤销或轮换；只修改网关数据库引用不能使已泄漏秘密失效。
3. 记录受影响版本和时间窗，停止向旧池分配执行，清理/排空旧连接；不能假定关闭池已撤销后端在途操作。
4. 核验新凭据的实际身份、目标、最小权限与TLS，以专门受权的有限连接检查验证，不以真实业务写作探针。
5. 尚未领取且绑定旧版本的计划失效；需要执行时新建Action及计划，受控写重新由他人审批，不悄悄换身份继续旧批准。
6. 已派发执行按事实收尾或核对；日志/工单若含秘密，限制访问并按既定留存处理，不复制秘密作故障样本。

恢复门槛：实际后端旧凭据处理结果已确认，新绑定与连接池版本一致，权限正反例通过，待执行旧计划不能获得资格。记录变更人、绑定版本、检查范围和未能召回的在途影响。

## 6 执行租约过期与旧实例恢复

进入条件：Execution心跳/租约过期、实例暂停后恢复、同一节点重启后仍看到旧执行者信息。值班人员需核对实际实例启动代际。

1. 扫描结果仅为候选；在处置前重新核对当前lease、claim token、owner、状态与hard deadline，避免使用陈旧快照打断正常执行。
2. 不把租约转交另一worker，不创建第二个Execution，不重新调用原生adapter；租约是健康信号，不是可重放队列。
3. 通过部署控制确认原实例、进程或容器的启动代际，隔离/终止正确执行者；不能仅按可能复用的主机名或PID判断。
4. 隔离确认前保留发送与效果不确定性；数据库fencing token无法约束不认识该token的PG、Redis或HTTP服务。
5. 原执行者发现续租失败时停止尚未发出的路径并尽力取消在途操作；该协作行为不能代替对失联/暂停进程的隔离。
6. 依据已有证据CAS更新为结果未知并告警；迟到可信结果可追加核对，不能把未知重新改为可领取状态。

恢复门槛：旧执行者不能再发送、受影响Execution已分类，且没有接管写派发。无法核验隔离时保持资源冻结，不以“新实例已健康”代替旧实例停止证据。

## 7 SIGTERM与有界关闭

进入条件：发布、缩容或正常停止。发布负责人确保停止流程与网关实际实现一致，不把固定等待几秒视为优雅关闭。

1. 关闭readiness，停止本实例接收新受控请求、新执行领取及新outbox领取；其他实例仍遵守同一持久资格约束。
2. 对已接收调用给予配置内的排空窗口，继续记录真实结果；窗口不能靠心跳无限延长执行hard deadline。
3. 到期后发适用协议/原生取消，关闭流和连接；取消响应不得显示为已回滚。
4. 对未确认效果保留派发意图与未知状态；来不及落库的窗口由恢复器发现，不重新派发补齐结果。
5. 完成数据库、连接池和通知worker关闭后退出；发布系统记录旧实例已停止的证据，再结束隔离。

恢复门槛：新实例迁移/身份/状态库就绪，旧实例停止及在途结果可解释。CONTROL_FLOW待批Action仍按期限与版本验证，不因部署获得新批准；BOUNDED_WAIT已结束的路径不恢复。

## 8 元数据备份恢复与跨实例写门禁

进入条件：从备份/PITR恢复、误删除回退或发现元数据事实缺失。恢复负责人先隔离写路径，资源负责人核对远端效果。

元数据备份不会回滚PG业务库、Redis或HTTP已经发生的效果；旧快照可能连已消费资格都不存在。仅恢复数据库并重启worker，可能把过去已执行的Action再次当成待执行。

1. 在恢复前停止新写入口及领取，隔离并确认终止所有旧实例/worker，处理仍可运行的旧版本和暂停进程。
2. 将全局写门禁保持关闭；控制门禁的恢复代际需由不随本次元数据回退的部署控制或独立权威保存并核验。
3. 为本次恢复生成新的recovery generation，记录恢复点、备份标识、应用版本及独立控制证据；不得只信任同一旧备份里的开关或代际。
4. 恢复元数据库后仅以核对/受限查询方式启动，验证schema、权限、密钥版本、备份完整性和数据时间线。
5. 将恢复得到的旧Action默认置于不可领取范围，冻结旧续传；网关签发的会话/游标/MRTR状态按恢复代际失效，不能复活旧批准。
6. 外部IdP access token不因恢复代际自动失效；仍验证其真实有效性与当前本地权限，需要重新授权时使用真实授权流程，不能伪称已吊销全部外部token。
7. 从不随本次回退的业务回执、原生状态及受控审计出口核对恢复点之后的领取和效果；缺失记录按未知处理，不推断未发生。
8. 检查所有新实例使用当前代际、旧进程已停止、旧请求无法领取；不能只验证一台实例或一次状态查询。
9. 按资源分批开放新Action；尚未明的业务对象继续冻结或走明确核对。需要新写时创建新计划、重新校验并由他人审批。
10. 保存开放范围与决定；回退本次恢复也须重新执行门禁与代际流程，不能把旧配置重新应用作为恢复捷径。

恢复代际是补充设计门禁，须在实现中绑定网关续传/领取上下文并验证，不是当前已存在功能。代际不可核验、旧实例无法隔离或外部效果无法确定时保持写冻结。

恢复门槛：独立代际和门禁可信、全实例代际一致、旧实例隔离确认、恢复点后效果已分类，且未知范围未被批量重做。不得以恢复库中的PENDING_APPROVAL、READY或NOT_DISPATCHED记录作为安全重放证明。

## 9 ChatGPT与认证/目录故障分流

| 观察 | 首查证据 | 处置与恢复条件 |
|---|---|---|
| 平台确认/阻断后网关没有请求 | ChatGPT产品面、账号/workspace、应用权限与平台提示 | 记录尚无网关Attempt；按平台能力处理，不伪造网关审批失败 |
| 工具缺失或旧Schema | 应用发布与refresh状态、工具快照版本、新对话结果 | 按平台刷新并复验；网关通知/TTL不能替代管理员刷新 |
| 共享应用显示工具但员工无资源权 | 当前员工授权、资源/数据范围、已发布元信息 | 调用仍拒绝；严格隐藏需按权限组发布并验收，不能靠显示列表授予权限 |
| 网关MCP 401/403 | 员工token受众/有效期、scope、当前本地权限 | 按真实OAuth登录/续期处理，不退为共享管理员token |
| 原生PG/Redis认证或API401/403 | 绑定凭据版本、实际后端身份与原生诊断 | 作为工具执行失败，走第5节；不触发错误的ChatGPT员工登录挑战 |
| 显示已批准但尚未执行 | Action模式、决定、有效期、是否有Execution | CONTROL_FLOW由原操作者新调用status/resume；回调不自动派发，先核对再续传 |
| resume后客户端未收到结果 | 原Execution与派发/副作用事实 | 查询既有状态或第2节核对，不以新工具调用重复业务写 |

首发ChatGPT账户/工作区与企业IdP、通知平台仍待确定；本手册不以假定套餐或私有客户端能力补齐故障。

## 10 只读诊断视图

实施时为值班角色提供有界诊断视图，沿用元数据模型字段并按组织/资源授权。下表是查询目标，不是绕过管理API的任意数据库访问授权；不提供修改资格或强制成功命令。

| 诊断问题 | 最少读取事实 |
|---|---|
| 某Action能否继续 | 当前state、row_version、interaction_mode、expires_at、cancel_requested_at及是否已有Execution |
| 是否存在发送证据 | Execution的dispatch_state、request_status、side_effect_status及受控evidence_ref |
| 是否为陈旧租约扫描 | 当前owner_instance、lease_until、hard_deadline和预期claim是否仍匹配，不向普通页面暴露claim token |
| 通知是否只是重复送达 | Outbox事件、去重关联、投递/业务响应和Action的可信Decision，不能只查IM消息文本 |
| 旧计划是否可用 | 当前资源/工具/凭据版本与计划绑定版本是否一致、计划密钥是否可用，不读取明文凭据 |

诊断导出只含必要关联与判断事实；完整参数、原生结果及证据另行鉴权。查询时点和当前版本必须一起记录，不能把一次旧快照当作后续处置的原子保证。

## 11 演练与关闭事件

关闭事件前核对：受影响实例与资源范围完整、剩余未知有负责人、资格记录未被删除/重置、后端效果计数与网关状态一致，权限和脱敏未因处置放宽。

演练至少覆盖：提交后丢响应、元数据库断连、通知重复、轮换旧池、过期扫描快照、旧worker暂停后恢复、SIGTERM排空、备份中缺失已发生写入及旧续传重放。关联[验证计划](validation-plan.md)的AC-07/09/10/11/12/13。

证据以真实运行结果填写PASS/FAIL/NOT_RUN；当前手册尚未演练，不能以评审、截图或旧脚手架构建代替恢复通过。企业网络已互通，本规程只验证既有接入与原生请求路径，不增加VPN、隧道或网络建设任务。
