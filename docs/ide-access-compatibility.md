# IDE 到企业网关的接入兼容方案

状态：拟议实现方案，尚未提供可安装网关或连接器。日期：2026-10-22。

IDE 内的 MCP Client 通过标准 MCP 接入企业网关，网关本身是 MCP Server。MCP 是这段连接的协议，不是位于 IDE 与网关之间的另一套业务服务。网关访问 PG、Redis 和 API 的原生适配不参与 IDE 的 MCP 版本协商。

首发客户端已选ChatGPT，主路径为远程HTTP；具体产品面、账户/工作区、工具快照与平台能力见[ChatGPT详细接入](detailed/chatgpt-access.md)。IDE接入程序仍是整体兼容目标，不因首发选择而删除。

## 1 两种接入路径

| 路径 | 使用方式 | 适用条件 |
|---|---|---|
| 原生远程 MCP | IDE 配置企业 HTTPS MCP 地址，直接完成远程授权与调用 | IDE 支持目标 Streamable HTTP profile 和兼容认证 |
| 本地 stdio 接入程序 | IDE 启动本地程序，程序完成企业认证并连接同一个远程网关 | IDE 仅支持 stdio，或其远程认证无法匹配企业要求 |

两条路径均为产品目标，可以分阶段开发，最终必须分别验收。客户端具备兼容的远程能力时优先直连；仅支持 stdio 时使用本地接入程序，仍经过同一个中央网关，身份、权限与审批要求一致。

示意入口为 https://mcpguard.company.example/mcp，此地址仅用于设计。具体 IDE 配置文件按实际客户端版本生成，不假定 Cursor、Claude Code 和 VS Code 使用相同配置格式。

本地程序暂称 mcpguard-connect，尚未实现。它只承担接入适配、员工登录与令牌保管、远程转发、取消及生命周期映射，不保存生产数据库凭据，也不自行决定批准或执行。

## 2 网关内部分层

| 层次 | 拟议职责 |
|---|---|
| HTTP 与身份入口 | TLS、受保护资源发现、access token 验证、主体上下文、容量限制 |
| MCP Server 协议层 | SDK transport、版本和能力、RPC 关联、工具目录、通知、取消和结果编码 |
| 统一工具调用层 | 将调用转换为可信主体、工具、参数、期限、action 与取消上下文，执行权限和策略 |
| 原生执行层 | 按不可变计划使用 PG、Redis、HTTP 适配器，返回结构化结果与执行证据 |

管理 API 与 MCP 入口分开，浏览器管理会话不能直接代替 IDE 的 MCP access token。两条 IDE 接入路径最终调用相同的工具处理器；不能为某个 IDE 复制一套放宽权限的业务逻辑。

## 3 原生远程接入流程

1. IDE 访问 /mcp。未取得有效访问令牌时，网关按 MCP 远程授权规范返回认证挑战和受保护资源元数据位置。
2. IDE 从元数据发现企业授权服务，完成适用的客户端注册或预注册、OAuth 授权码与 PKCE 流程。企业已有登录可用于识别人类，但仍需签发面向网关的 access token。
3. IDE 携令牌重试。网关验证令牌有效性、目标受众与权限，形成可信员工主体；不信任请求自报的用户名。
4. MCP Server 按客户端 profile 处理发现、初始化或每请求元数据。2025 与 2026 的行为分别处理，不统一要求 initialize。
5. IDE 查询 tools/list。网关返回该员工有权使用的工具及 Schema，完成全部分页及必要的版本化缓存。
6. IDE 调用 tools/call。处理器校验参数与资源权限，生成计划，决定放行、阻断或人类授权，再调用原生适配器。
7. 网关把结果编码为该 profile 的标准工具结果，并关联审计；原生服务错误不冒充 IDE 到网关的认证错误。

令牌续期和重新登录必须单列测试。退出、撤权或组权限变化后，不能依赖此前工具目录缓存继续调用。身份与资源权限在每次受保护操作中检查。

## 4 stdio 接入程序的职责

程序向 IDE 提供 stdio MCP 接入，对远程网关使用标准 HTTP MCP。首版按同 profile 做传输适配，不承诺任意新旧版本的语义转换。

- 完成员工 OAuth 登录、续期和注销；优先使用系统凭据库安全保存面向网关的令牌。
- 不将 token 放在命令行参数、配置 URL、stdout 或普通日志中，不使用全员共享管理员 token。
- stdout 只输出 MCP 消息，诊断写 stderr；保持长驻读写循环。
- 正确处理 HTTP 结果流、通知、进度与对应请求的取消，不能同步一写一读阻塞全部调用。
- IDE 退出时清理本地等待和远程请求；按实际 profile 区分断连与取消。
- 上报清晰错误：无法登录、版本不匹配、权限不足和远程不可达分别表达。

如果采用本地与远程分别终止的 SDK 连接，能力声明和 ID 映射也需独立验证。接入程序不能宣告自己无法转接的能力；本地 stdin/stdout 可用不等于远程协议已兼容。

## 5 版本与能力策略

建议固定官方 Go SDK 版本，优先验证 2025-11-25 和 2026-07-28 的工具能力子集。SDK 能解析其他旧版不等于产品已承诺支持；只发布实际验收通过的组合。

2025 profile 处理 initialize、initialized 和其版本的通知及会话；2026 profile 处理 server/discover、每请求版本与能力、订阅以及该版取消规则。版本探测使用标准发现或握手，不能用写操作试探。

不按 User-Agent 或 clientInfo 的产品名称授予权限。实际版本和能力决定线上的协议行为，客户端产品名称仅帮助诊断和建立测试记录。

| 能力差异 | 降级方式 |
|---|---|
| IDE 不支持远程 MCP 或兼容的远程认证 | 使用已验收的本地 stdio 程序，身份要求不降低 |
| IDE 不支持 elicitation | 使用企业审批页或 IM；不强发未声明的 elicitation 请求 |
| IDE 未支持 Tasks 或相应长时交互 | 使用普通调用的有界等待，或明确的业务续传；不伪造异步任务响应 |
| IDE 结果展示能力有限 | 按 profile 同时提供标准文本摘要与允许的结构化结果，不静默丢数据 |
| IDE 不接收某种目录变更通知 | 依标准重新发现或重连，调用时仍重新鉴权；不靠缓存授予权限 |
| 无共同支持版本 | 清晰拒绝，记录版本诊断；不删字段假装兼容或匿名回退 |

首版优先 tools/list 和 tools/call。其他能力实现且通过相应客户端验证后再声明。工具注册和 Schema 来自网关，PG、Redis、API 不参与 MCP 能力声明。

## 6 工具调用的一致性

例如网关提供 redis.get，输入中包含已注册 resourceId 和 key。IDE 只按工具 Schema 提交业务参数，网关从注册表取目标与凭据，校验该员工对 key 范围和操作的权限后执行原生 Redis GET。

每种 IDE 使用相同业务工具和权限规则。协议层将请求归一为调用上下文，包括可信主体、协议 profile、工具及定义版本、业务参数、原始 RPC ID、期限和取消上下文。

action ID 对应业务意图，RPC ID 对应本次 MCP 尝试，execution ID 对应一次执行领取及派发跟踪，记录存在不证明已发送；未领取时 execution ID 为空。两个员工同时使用 id:1 不应串结果，MRTR 新 RPC ID 也不能绕过原计划绑定。

输入错误、工具执行错误、权限拒绝和结果未知采用明确契约。保留工具输出 Schema、数值与二进制编码信息；适配器完成业务转换，MCP 层只按 profile 编码。

## 7 人类授权不能破坏 IDE 生命周期

普通调用的建议基线是有界等待，不依赖 IDE 私有插件。批准在有效调用内到达时继续，拒绝、过期或派发前取消时结束并明确未执行。等待窗口由具体 IDE、接入程序、HTTP 路径和后端预算实测，不能先假定固定五分钟可用。

2026 MRTR、URL elicitation或Tasks作为逐项验证能力，不因为规范存在就默认客户端已支持。MRTR授权状态由网关核验决策人身份与资格后认定，客户端inputResponses或accept不能自证批准；首版风险分级与受控写他人审批已定，具体身份源仍待定。

普通最终响应后不补发同一 RPC 的结果。普通有界等待已结束且未派发时，迟到批准不启动执行；受控续传按其单独的 action 契约处理。

用户点停止、请求超时和网络中断分开测试。2025 HTTP 断连不能通用地当取消；2026 按对应请求流取消。原生服务已收到写请求时，取消仅能尽力处理，副作用未知不得误报已回滚。

## 8 拟议端点和配置交付

| 接口或产物 | 作用 |
|---|---|
| /mcp | IDE 使用的统一 MCP 资源入口，HTTP 方法与行为按所选 profile 处理 |
| 标准受保护资源元数据地址 | 提供 resource、授权服务器与相关发现信息；按资源 URL 实现规范路径 |
| 企业授权服务 | 处理员工授权、PKCE、token 签发与续期，具体平台待选 |
| /api/v1 下的管理接口 | 注册资源、发布工具与策略、处理授权和查询审计，由浏览器或管理客户端使用 |
| 各 IDE 的接入配置 | 按客户端及版本生成远程地址或本地程序配置，配置中不包含生产资源密码 |

普通 IDE 只需理解标准 MCP 与受支持的认证。企业管理 REST API 不混入 MCP 方法名，也不要求普通 IDE 学会管理端内部接口才能进行基本工具调用。

## 9 兼容矩阵与发布门槛

首发客户端已选择ChatGPT，优先验证远程HTTP入口；账号/工作区、产品界面和实际MCP能力尚待核实。stdio另以实际支持的客户端验收，候选包括Cursor、Claude Code、VS Code具体扩展；不能据此宣称ChatGPT可启动本地连接器。当前所有产品组合均未实测。

每个组合记录：客户端和扩展版本、操作系统、原生 HTTP 或 stdio 接入、协议 profile、认证方式、实测等待窗口、通过的能力及已知限制。

| 验收 | 通过标准 |
|---|---|
| 安装与建连 | 按生成配置可连接，协议发现或握手正确，版本不匹配可诊断 |
| 登录与权限 | 首次登录、续期、退出、撤权和两员工隔离正确，不共享管理员凭据 |
| 工具目录 | 权限过滤、全部分页、Schema、缓存与目录变更正确 |
| 调用与结果 | 无害读取和受控写入可完成，标准文本和结构化结果可消费 |
| 人类授权 | 批准、拒绝、过期和能力降级明确，不把待授权误报已执行 |
| 取消与故障 | 点击停止、超时、断线按 profile 处理，迟到批准不触发新写入 |
| 并发隔离 | 多员工、多资源、相同 RPC ID 不串线，每条执行可关联审计 |

HTTP 直连和 stdio 接入各至少一个真实 IDE 的完整组合通过上述核心门槛，并发布可复现配置与记录；其他组合逐项放行。两条路径分别验收，不能用其中一个通过代替另一个。

沙箱先使用官方 SDK 测试客户端和独立语言客户端验证同一网关，再连真实测试 PG、Redis 与无害 API，最后用目标 IDE 验收。标准建连和工具发现通常无需模型 key；自然语言触发与模型消费结果使用实际 IDE 的模型会话验证。

## 10 实现起点

建议使用官方 Go SDK v1.8.0 的 MCP Server 与 transport，按其 Go 1.25.0 要求升级当前 Go 1.22 项目；此为实现建议，尚未变更代码。SDK 支持 profile 不等于 Tasks、企业认证和具体 IDE 已开箱通过，需要分别验收。

详情依据见[协议接入设计](mcp-protocol-design.md)中的固定版本规范与 SDK 来源。下游原生执行见[适配设计](native-adapter-design.md)，不新增后端 MCP 连接。
