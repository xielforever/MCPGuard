# 多资源自助访问验收矩阵

版本：v0.2。日期：2026-10-24。所有业务场景状态为 NOT_RUN；本轮仅校验设计文档，未执行本表测试。原 [验收计划](../../detailed/validation-plan.md) 和既有证据保留，不能据旧成绩将本表标为 PASS。

## 1 无害夹具和证据层次

至少使用两套独立业务 PG（含相同库名/账号名的反例）、一个独立元数据 PG、Alice/Bob 两个调用主体、一个有指定资源审批资格且无业务自批权的 operator。业务原生账号按主体/资源/套餐隔离；读写权限、视图/RLS 和固定模板必须在实际数据库落实。

提供方分别模拟可核对成功、创建后响应丢失、权限不符和清理失败；同时保留真实 PG 账号创建/权限查询和取消证据。Redis/HTTP 扩展使用原生隔离实例，不能拿一个模拟下游 MCP Server 代替。

证据分为文档检查、契约/单元、真实后端集成、HTTP/stdio 协议、客户端私有交付、模型可见原生调用、人工体验和部署。每层单独标记 PASS/FAIL/NOT_RUN/NOT_APPLICABLE；NOT_APPLICABLE 说明原因，不能计通过。

## 3 完整流程验收脚本（待执行）

### 场景 A：首次读取

Alice 以一个 MCPGuard 配置登录，列举两套可见 PG，只对订单库申请只读套餐。operator 决定后先观察 PROVISIONING，再核对原生账号/权限和 ACTIVE。可信组件准备并领取密文、保存和激活，模型以 resourceId/credentialId 调用固定读取，服务端使用正确原生身份返回业务结果。Bob 使用相同业务参数及复制来的文件必须失败；两人的目录、账号、结果和审计各自正确。

### 场景 B：资源权限与单次写批准

Alice 获得允许申请固定写操作的资源套餐及对应包，发起一条固定更新。资源授权不使该写立即执行；具体计划待批。operator 批准后仍不派发，只有 Alice 的显式 resume 能取得资格。修改参数、换资源或换身份/版本不能复用批准。原生效果计数与永久资格记录核对一致。

### 场景 C：文件吊销及后续使用

在已下载且已激活、连接池已有连接的状态下吊销一个包。分别用原文件、旧文件备份、已有 context、另一个进程/副本、待批 Action 和历史结果接口重试；新领取一律失败。无关的另一用户/资源不受误伤。原生清理不是这一文件级吊销生效的前提，页面明确显示其适用状态。

### 场景 D：撤权与未知窗口

分别把故障放在资格领取前、意图提交后发包前、PG 正在执行、写提交回应丢失和结果交付阶段。记录撤权提交顺序、实际后端效果和停止核验，不能将取消请求等同回滚。完成事实保留，未知写不重放；原生清理失败在网关保持拒绝时单独处置。

### 场景 E：凭据服务、网关及备份恢复

中断密钥服务、权威元数据、客户端领取与原生提供方，证明新执行失败关闭且不外发明文。恢复服务不续活撤销记录。将元数据恢复到撤销前快照后，执行、激活与签发被 fence 阻止；完成吊销和账号事实核对或废止旧 epoch 后，才能按重新核验的有效授权继续。

## 4 证据最小字段

每条记录包含 sourceSnapshot/commit、fixture 版本、客户端/入口/profile、orgId/principalId、resourceId/configVersion、requestId/decisionId/jobId、grantId/version、credentialId/leaseId、context 的非秘密标识、Action/Attempt/Execution、预期与实际、原生身份和效果证据、撤权排序、退出码及限制。

不记录员工 token、context 令牌、密文字节、原生密码、完整 DSN、敏感参数或未脱敏结果。哈希、对象 ID 和脱敏摘要的可见性同样受审计权限控制；密文不可读不能作为允许日志收集的理由。

局部阶段可先形成对应证据，最终统一完成一次真实客户端闭环。未实现、未执行、客户端能力不支持及真实企业集成未接通分别标记，不互相代替。
