# 加密凭据、客户端与吊销生命周期

版本：v0.2 设计增量。日期：2026-10-24。状态：NOT_STARTED；下列文件格式、私有接口和客户端命令均为待实现目标。字段和状态以 [领域契约](contracts.md) 为准。

## 1 已确定的安全边界

用户已选择由 MCPGuard 服务端建立数据库连接，终端只收到业务结果。终端不得取得原生密码、解密密钥、原生认证 handle 或可任意操作的已认证连接。文件只在 MCPGuard 内部验证和消费，不提供面向终端的 decrypt、密码导出或无限制数据库隧道。

“只下发密文”与“在线撤权”同时成立。客户端持有旧文件、复制文件或恢复本地备份，都不能使被撤销的服务端使用资格重新有效。网关、权威状态或必要密钥服务不可用时停止新执行，不回退到本地解密或直连。

文件不可读不等于可以免认证使用；密文和激活上下文都按敏感凭据处理，不放进模型参数、聊天正文、普通日志或公开管理导出。

## 2 文件内容和密码学处理

首版文件扩展名为 .mcpguard，逻辑格式为 versioned authenticated envelope。使用成熟实现的 AEAD，算法由版本化允许列表固定，首版工程候选为 AES-256-GCM；不接受客户端选择算法或外部 key URL，不自行设计密码算法。

| 层 | 内容 | 处理 |
|---|---|---|
| 明文封套 | formatVersion、issuer、keyId、nonce、ciphertext、authenticationTag | 全部限制长度和编码；版本、issuer 等通过 AAD 或密文一起认证；封套未验证前均不可信 |
| 加密载荷 | credentialId、leaseId、orgId、subjectId、resourceId/configVersion、grantId/grantVersion、bindingId/bindingVersion、profileId/version、issuedAt、expiresAt、issuerEpoch、audience | 服务端验证与当前权威记录匹配；audience 固定为本部署的网关执行用途 |
| 不包含 | 原生密码、DSN、OAuth refresh token、解密密钥、审批秘密、可执行脚本 | 原生秘密仅存在服务端 SecretProvider，文件中只有内部绑定引用 |

唯一 nonce 和随机材料由受信密码随机源产生，按密钥版本避免重用。解析拒绝重复键、非规范编码、超限长度及未知版本；完整性验证失败使用统一安全错误，不返回解密细节或部分载荷。

AAD 编码规范、nonce 长度、允许算法、精确字段类型与上限须在 RA-01 的单一版本化机器契约中固定，并覆盖篡改反例后才能实施；本轮没有创建可执行加密实现或宣称密码审计通过。

包加密密钥、原生秘密存储密钥与现有计划 HMAC 密钥分别管理。生产通过 SecretProvider 接入组织选定的 KMS/秘密系统，密钥不与密文以同等权限保存。隔离开发环境可用受保护测试密钥，不计作生产托管验收。[OWASP 加密存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)

## 3 签发、一次领取与本地保存

1. credential.prepare_download 只接受本人 ACTIVE 授权；在元数据事务外准备密文及受控 blob，再在事务内重新检查主体、资源和套餐版本，写 CredentialLease、Package、DownloadTicket 与审计后才开放领取。准备失败或事务未提交的孤立 blob 不产生资格，按受控清理处理。
2. MCP 结果只返回非秘密标识、状态和期限。downloadId 不是可持有即兑换的令牌，不放到免认证 URL 查询参数中。
3. 受控组件通过私有 HTTPS 接口认证领取，服务端重验当前主体、对象归属、授权和 ticket。claim 原子消费后发送密文文件，响应禁止缓存，文件名由服务端生成。
4. 保存到系统用户私有目录，使用受限 ACL、原子写入和固定格式校验；不默认保存到代码库、共享工作目录或同步公开目录。文件不得携带启动命令、插件安装或任意配置覆盖能力。
5. 领取响应丢失时查 ticket 状态。新 ticket 可重新交付同一仍有效的包；不复用已消费 ticket，不重新创建授权或原生账号。若包已撤销，不提供历史密文重取。

服务端采用加密 blob 存储或受控引用，不把密文复制到普通审计。下载完整性摘要只用于判断传输结果，不能替代主体、当前状态或 AEAD 校验。

一次性交付只缩短领取暴露窗口；已交付文件后续可重复用于获准调用，并在每次使用时受在线状态约束。两者不是同一个“只用一次”。可参考已有的一次性交付机制，但不能把可兑换秘密的包装令牌暴露给模型。[Vault Response Wrapping](https://developer.hashicorp.com/vault/docs/concepts/response-wrapping)

## 4 一个 MCP 配置访问多资源

标准 MCP 工具结果可以返回内容或资源链接，但不保证远程服务能把文件写入本地凭据库；客户端能力须实测。[MCP 工具结果](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

目标体验为一次安装或启用受控客户端组件、一个网关配置、每位用户独立登录；发现并申请新资源后，无需逐库填写 DSN、密码或新增 MCP server 条目。组件只负责传输、密文保存和上下文管理，解密与原生执行仍在服务端。

### 4.1 多资源激活上下文

1. 组件认证后建立 CredentialContext，私有通道取得高熵随机上下文令牌；服务器登记 clientInstanceId，只保存令牌 verifierHash、归属和期限。clientInstanceId 是索引，客户端自报设备名不取得可信设备身份。
2. 下载的每份 .mcpguard 文件通过 POST /credential-contexts/{id}/activations 递交。服务端验证完整性、当前归属、授权及版本，创建 context 与 credentialId/resourceId 的激活映射。
3. 后续 MCP HTTP 请求自动携带员工认证以及 X-MCPGuard-Credential-Context。该头不是 MCP session ID，也不能单独代替员工认证；仅用于证明当前已认证客户端的激活上下文。
4. 模型调用业务工具只提供 resourceId、credentialId 和业务参数。服务器根据当前 context 查对应激活，随后重验包、授权、资源、策略及版本。
5. 同一 context 可激活多套资源。新增资源更新服务端映射，不要求每次调用重新运行本地 helper；删除本地文件可清理缓存，真正停用仍通过服务端吊销。

组件在登录/建立 context 后，通过私有 GET /credential-downloads 有界同步本主体、本 clientInstanceId 的待领取任务，或按用户明确操作立即同步。prepare_download 从已验证的当前上下文登记对应客户端任务；缺少上下文时只能准备本人认证后的手动领取，不能伪造自动激活。组件完成领取、保存、激活后回写非秘密状态。HTTP helper 只负责提供头，自动领取需要受控组件的同步循环，不能假定命令会在每次 RPC 被调用。组件重启先核对任务与 ticket 状态，不能盲目再次申请账号或生成新授权。

context 令牌不返回模型，不能写普通日志或随浏览器跨来源转发。创建/重建 context 不自动激活所有授权，必须重新递交仍有效的本地密文。context 过期只允许重建客户端上下文，不续活 REVOKED 包。

### 4.2 两条入口与能力矩阵

| 客户端组合 | 目标接入 | 必须单独证明的能力 | 设计时状态 |
|---|---|---|---|
| 本机 coding 客户端原生 Streamable HTTP | 一个 /mcp 配置加本地凭据 helper；helper 使用私有 API 下载、激活并供给认证头 | 私有领取不进入模型，头缓存更新可控，多资源选择与逐次撤权有效 | NOT_RUN |
| 支持 stdio 的 coding 客户端 | 一个 mcpguard-connect 配置，连接器转入同一 HTTP 网关 | stdout 纯 MCP 帧，组件安全缓存与多用户隔离；不访问原生数据库 | NOT_RUN |
| 纯远程 HTTP、无本地私有钩子的客户端 | 可先使用目录、申请和状态；可经受认证网页手动下载文件 | 完整执行须另验安全激活/客户端上下文能力；网页下载不算自动配置通过 | CAPABILITY_PENDING |

Codex 的 HTTP helper 可以返回认证头，但头会在连接中缓存，不能假设每次工具调用重新读取文件。因此服务端 ContextActivation 和每次在线授权校验承担动态资源及吊销，不把安全性放在 helper 调用频率上。[OpenAI 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

同步组件在 context 到期前通过私有 renewals 接口重验员工及当前上下文，在不改变令牌且未超过绝对期限时更新服务端期限，避免依赖每次刷新头。context 已过期、令牌必须轮换或达到绝对期限时重新建立上下文，头更新/重连使用该客户端实际支持的方式；没有此能力就明确要求刷新连接并记为能力限制，不能承诺完全无感续期。

包或 context 的业务错误不得伪装成 401/403 来诱导 helper 重发写请求。入口员工认证挑战须发生在受理业务之前；如果已经创建 Action 或领取执行资格，认证恢复后查询原操作，按原资格协议恢复，不再次提交未知写。

URL-only 客户端没有相应私有能力时，明确返回 CREDENTIAL_REQUIRED 或未支持状态。不能将密文、上下文令牌塞进模型正文，也不能悄悄仅凭资源 ID 执行，以此假称完成本增量。

## 5 使用时的在线检查

执行准入同时要求：当前员工身份有效、context 有效且归属相符、对应激活存在、包认证有效、CredentialLease/Package 为 ACTIVE、AccessGrant 为 ACTIVE、有效期未到、资源与绑定版本相符、本次工具操作及必要具体批准合格。

Bob 即使复制 Alice 的文件，也不能用自己的登录身份激活或使用；解密得出的 subjectId 不能取代当次已认证主体。请求自报的 deviceId 或用户名不构成设备绑定，需要时另接注册公钥及持钥证明，不将设备名字符串当成安全保证。

认证与授权在每次受保护请求中检查；MCP session、TCP 连接、已激活的 context 和已建立的 PG 连接都不能代替当前授权。[MCP 安全规范](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)

仅验证封套或离线检查文件到期时间不足以实现单份吊销。权威库不可达时不能使用进程缓存或文件内旧权限继续接受新执行。

## 6 续期、轮换和长期缓存

员工登录 token、context、加密文件租约、资源授权、原生秘密和具体 Action 分别有生命周期。期限由资源及企业策略显式配置，不在本文虚构统一生产数值；包期限不得超过关联授权和套餐允许上限。

当前授权仍有效时，可信组件可自动请求替换包或 context，并保留原状态关联；若授权过期或已撤销，必须重新申请。普通启动、登录续期或客户端重启不恢复被撤销权限。

原生秘密的 secretVersion 可在保持相同实际身份和权限语义时轮换，稳定 bindingVersion 允许已有引用包继续定位当前凭据。每条新业务计划仍固定当时的 secretVersion；已待批或已获批但尚未领取的旧计划按原规则失效并重新生成，不悄悄换秘密版本执行旧批准。

原生身份、资源目标、权限套餐或授权范围变化必须更新语义版本，旧包拒绝使用并重新签发；扩大授权须重新决定。包加密 keyId 的轮换保留受控解密窗口或主动重签，单份吊销不通过销毁共享主密钥实现。

## 7 吊销作用域和可观察状态

| 吊销对象 | 立即受影响的网关访问 | 原生侧处理 |
|---|---|---|
| 单份 CredentialPackage | 该文件、其 lease 和所有激活映射；其他仍有效包按自身授权处理 | 通常不必轮换未外发的原生密码 |
| AccessGrant | 该授权的所有包、激活及尚未取得资格的操作 | 按托管边界撤销该授权拥有的角色/权限，账号无其他合法依赖时清理 |
| 主体禁用或资源停用 | 对应主体或资源全部当前访问 | 淘汰相关池；按策略停止在途操作，保留无关账号和他人访问 |
| 密钥/原生凭据泄漏 | 受影响 keyId、binding 或 secretVersion 的范围，停止新派发 | 轮换或撤销相应秘密，核对影响；不把普通文件吊销扩大成全企业密码轮换 |

撤销事务更新权威状态、authEpoch、审计和需处理事件，与执行领取按统一授权 head 排序。事件用于加快淘汰池和通知；即使事件丢失，下一次领取仍必须查库拒绝，不依赖最终一致缓存实现核心安全性。

gatewayAccess=REVOKED 代表新的使用资格已关闭。inFlightStop 与 nativeCleanup 独立报告：取消请求已经发出不等于执行已停止；数据库清理失败也不取消网关吊销。控制台展示撤销提交时间、影响范围、仍在执行的操作和清理错误，不笼统显示“全部撤权成功”。

PG 的终止接口在未等待确认时可以只表示信号已发送；实现必须核验实际结果。已提交的写入和已交付结果不能通过文件吊销撤回。[PostgreSQL 会话控制](https://www.postgresql.org/docs/16/functions-admin.html)

结果资格检查与网络发送之间也存在在途窗口。观察到撤权后停止后续敏感交付；已发送或已进入发送链路的数据按实际记录，不能承诺撤权提交瞬间所有客户端接收都归零。验收核对资格/发送检查时点和实际已交付范围。

## 8 故障与历史访问

| 场景 | 处理 |
|---|---|
| 领取中断、并发 claim | ticket 原子消费；核对提交状态，再用新 ticket 重取同一有效包，不能多开账号 |
| 凭据服务不可用 | 拒绝新签发/执行，保留现有事实；不返回原生密码作为应急回退 |
| 撤权与审批、账号开通或 resume 并发 | 当前状态和 epoch 决定资格；迟到决定/开通结果不能恢复已撤销授权 |
| 旧包、旧 context、旧连接池或另一副本缓存 | 重新验证当前权威状态；旧缓存不授予执行权 |
| 撤权时查询结果正在生成 | 按策略取消并停止后续敏感结果交付；已交付部分据实保留，不能宣称回收 |
| 通过历史结果、导出或重放管理响应读取 | 敏感结果要求当前资源授权；已撤销后仅保留独立授权的审计摘要可见 |
| 备份恢复丢失较新撤销记录 | 开启 recovery fence；核对独立保留的撤销证据，必要时废止旧 issuerEpoch 并重新核对授权；未完成前不签发、不执行 |

退出登录关闭服务端 context 和激活，再清理本地缓存；本地清理是便利措施，不是撤权前提。服务端不接受将旧 REVOKED 状态更新回 ACTIVE 的普通续期命令。


## 9 RA-07 已实现边界（2026-10-26）

服务端现可从当前 ACTIVE 个人授权签发只含引用的密文包。租期取显式策略上限与授权到期的较早值，issuer/策略递增版本变化严格使旧包失效。相同 requestKey 返回同包；并发失败的多余 nonce 预留不复用。

使用包必须同时验证当前主体 token、本人包记录、AEAD 完整性、完整引用与摘要、授权/资源/套餐/个人绑定、issuer/keyId/issuerEpoch、策略版本及租约。密钥不可用时不放行，但查询状态和服务端关闭租约不依赖解密。ACTIVE 租约只转为 REVOKED/EXPIRED，不能借资源恢复、重启或文件副本重新激活。

内部单包关闭已可证明旧文件在线失效，完整公开撤权入口、账号清理传播和在途停止仍属 RA-13/14。当前 CLI check 是服务器操作，不输出解密内容；客户端下载、缓存、Context 和正式读取尚未开放。详见[说明](../../credential-packages-local.md)及[验收](../../validation/local-ra07-2026-10-26.md)。


## 10 RA-08 已实现边界（2026-10-26）

本人 ACTIVE 授权可准备短期 ticket，独立私有组件以当前员工认证和单独的下载授权一次领取密文；模型只取得标识和状态。没有 Context 时只支持 MANUAL_OWNER，clientInstanceId 不由模型自报。私有授权文件不包含服务器或数据库密钥，原生秘密仍由服务端解析。

READY 只转 CLAIMED/EXPIRED/CANCELLED；消费先于响应提交。未到服务端的中断可查状态后明确重试，消费后丢响应必须新 ticket，原包/租约/账号不变。组件完整校验后原子保存，错误/输出/日志/审计不带包或私有令牌；服务器写入结果不等于客户端保存或激活。

本地缓存索引、自动同步、Context、跨资源激活和续期留给 RA-09；Windows ACL 和原生客户端仍未验收。详见[私有交付说明](../../private-downloads-local.md)与[验收](../../validation/local-ra08-2026-10-26.md)。


## 后续 RA-09 状态（2026-10-26）

登记客户端、Context、私有缓存、有界同步、多资源激活和续期现已实现。Context 续期与包/租约追加续期独立；两者都不能重建已撤销包或改变原生账号。Context 重建先清空激活，再验证实际本地文件。原设计与 RA-07/08 时点保留，见[RA-09](../../credential-contexts-local.md)。


## 后续 RA-10 客户端能力（2026-10-26）

HTTP helper 的一次 stdout 属于宿主私有头回调，不能交给模型；持续私有同步由独立 worker 驱动。Context 短续期保持头，换头需宿主重连；stdio 私有模式每请求更新内部头，自然 EXPIRED 在下一调用前重建并重验文件，REVOKED 需显式私有修复。URL-only 不宣称自动私有交付。能力、配置和实际验收层次见[RA-10](../../private-client-adapters-local.md)，前文设计和时点保留。
