## 4 实施位置与兼容方式

后续预计在 gateway 的工具/私有 HTTP 入口、metadata 的授权和执行事务、nativepg/controlled 的连接解析、客户端接入组件及当前内嵌控制台实施。新模块职责按架构分层，文件路径在开发时决定；本文不创建占位代码。

运行配置拆分启动依赖与动态资源目录，去除新路径对一个全局 BusinessDSN/WriterDSN 的依赖。原本机演示适配仍由显式配置启用，保持原端口、数据和日志。生产资源、权限和账号不从夹具自动生成。

原 pg.get_demo_item 等演示工具不直接更换 Schema。新版本工具显式带 resourceId/credentialId，复用已有受控操作和结果封套；权限和版本不兼容时返回明确错误，不悄悄绑定任意可用资源。

旧 /api/v1、固定 demo 工具和新 /api/v2 分别声明可访问资源集合，不能给新资源挂载一个不要求凭据包的旧入口。旧演示端点可继续服务原夹具，不授予新生产资源访问。

## 5 迁移和回退步骤

1. 固定实际源工作树，备份元数据、版本配置、二进制及秘密引用元信息；保留失败现场和全部旧验收。备份不包含公开导出的原生密码。
2. 仅增加新表、约束和版本化接口；旧 Action、Attempt、Execution、审计顺序和加密结果不改写。迁移账号独立于普通运行及开通账号。
3. 为两套隔离 PG 建立显式资源、套餐与账号提供方配置，逐项验证，再启用新路径；没有当前授权则不签发凭据。
4. 不把 Alice 的演示 token、共享 demo 账号、全局 scope 或已完成历史 Action 自动提升为企业授权。既有真实授权需明确导入来源、核验账号及由负责人确认范围。

   迁移须核对新旧路径的物理目标、schema/表及数据范围重叠。纳入 v0.2 的目标不能继续让同一主体经旧无包接口访问相同数据；先关闭旧映射或明确隔离旧夹具。仅改 resourceId 或接口版本不足以避免旁路。
5. 先验证目录和申请，继而验证私有下载/激活与只读，再启用受控写及原生客户端验收；验证期间保留原本机路径和数据。
6. 回退优先关闭新功能入口、停止签发和执行、保留新表与墓碑。旧二进制无法理解新增授权/撤销时，不得用它服务新资源；需要只读运维模式或停服，不通过删除迁移表恢复表面兼容。
7. 元数据恢复保持 recovery fence；吊销历史与原生副作用未核对前，不签发、不激活、不派发。必要时更新 issuerEpoch 使全部旧包失效，并重新核验授权。

## 6 验证与交付记录

开发阶段使用真实隔离 PG、测试身份、固定操作及受限提供方；账号创建和撤销也属于需要实际后端证据的副作用，不能只测内存状态。新测试随对应实现添加，本轮不创建或运行业务测试。

每个阶段记录目标源快照或提交、入口、身份、资源和原生身份、授权及包版本、预期与实际、审计和原生效果、退出码、失败现场及限制。通过已有 SDK 不代表原生客户端已完成安全下载和使用。

真实客户端验收安排在功能与本地检查完成后统一进行，避免每个小项反复重启客户端。若客户端不支持所需私有能力，记录 CAPABILITY_PENDING，继续可独立推进的工作，不以其他 SDK 脚本替代原生通过。
