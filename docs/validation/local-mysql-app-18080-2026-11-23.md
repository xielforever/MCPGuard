# MySQL App 本机 18080 升级验收

2026-11-23（新加坡时间），将本机 `127.0.0.1:18080` 的 MCPGuard 升级到 [PR #32](https://github.com/xielforever/MCPGuard/pull/32) 合并后的 `7e7bb92d51b24233362ab36747d733f230553e98`。部署工件与 PR #32 的 DSH 复跑工件 SHA-256 一致。生产部署继续暂缓。

## 升级与保留核对

1. 从本机备份恢复隔离副本，在元数据 004 上验证旧网关、原控制台登录、MCP 读取和历史结果。随后在副本应用 005、006、007，验证原行保留和 MySQL 工具可用。
2. 在本机停止旧网关后备份元数据。将原库克隆并在副本上运行迁移，再切换网关。保留原元数据库、旧网关容器和可读取的升级前备份。
3. 切换并验收后按行指纹核对。原有连接配置、4 个主体、5 条工具授权、4 条审批授权和 215 条历史审计记录均保留。Windows 健康检查及控制台均返回 HTTP `200`。既有管理员和普通用户可登录，13 项旧 MCP 工具及原历史结果仍可访问。

元数据 004 上的连接配置来自当时的原生适配器配置。升级后控制台开始支持 App 登记。本机连接器的出站范围为 `127.0.0.1/32`。

## 本机 Chrome 和 DSH 实测

运行 `43593161eccd` 使用 Chrome、安装版 DSH `0.2.2-rc.5` 和临时 MySQL `8.4.11`。Chrome 完成测试 App 的登记、测试、授权和启用。DSH 经 Streamable HTTP 调用本机网关。

| 验收项 | 实际结果 |
| --- | --- |
| 表目录 | `connector.mysql.list_tables` 返回 `commerce_catalog` 的 `orders`、`products`。 |
| 字段 | `connector.mysql.list_columns` 返回 `orders.id`（`bigint`，不可空）和 `orders.order_status`（`varchar`，可空），包含字段顺序。 |
| 单库限制 | 原生 MySQL 测试账号可见旁库。MCP 拒绝旁库和大小写变体中的元数据、跨库限定名、显式覆盖数据库参数及视图字段。 |
| 停用与审计 | 测试 App 停用后，原 DSH 会话再次调用返回 `ACCESS_DENIED`。已读回创建、测试通过、启用、停用审计，临时 MySQL 已清理。 |

**单库只读和停用验证通过，原始本机运行报告仍标为 `PARTIAL`。** 第二个既有 DSH 身份的令牌返回 HTTP `401`，无法建立有效会话。本机未获得第二身份的 App 授权拒绝证据。现有主体及授权保持原值。先前在隔离夹具完成的未授权主体测试见[功能验收](local-mysql-app-2026-11-22.md)。
