## 实现与实际结果

| 项目 | 本轮结果 |
|---|---|
| 管理身份 | 新增独立 mcpguard-provision；元数据工作角色与网关角色分开，原生管理运行角色无 SUPERUSER/CREATEROLE/CREATEDB/BYPASSRLS，只能调用固定管理函数 |
| 新建账号 | 两套 PostgreSQL 16.14、Alice/Bob 四个不同个人 LOGIN；模板固定 SELECT + owner_name/current_user RLS，实际连接返回各自数据，跨身份行不可见 |
| 既有账号 | 需管理员明确登记主体/资源/套餐/版本及个人秘密引用；以真实凭据核验成功，密码未改动；危险角色、成员关系、列写、schema CREATE、管理函数权限或错密码均拒绝，失败不修改其 LOGIN |
| 激活版本 | 批准 v1 保持 PROVISIONING 的批准快照；真实核验、当前资格/配置/期限/绑定版本复查后，原子写入观察、账号、绑定、VERIFIED、授权 v2 / ACTIVE 及审计 |
| 并发/未知 | 八个并发调用只派发一次原生创建；回执丢失保留 OUTCOME_UNKNOWN / PROVISIONING_UNKNOWN，重放不新建或激活 |
| 迟到与失败 | 开通后资格移除、配置版本改变或到期均不激活；关键激活审计失败整体回滚；新建账号失败最佳努力 NOLOGIN，任务保留 CLEANUP_PENDING |
| 服务端秘密 | 原生密码密文存储，按组织/账号/版本绑定 AEAD；当前资格或 ACTIVE 失效后服务端不再解析秘密；客户端状态仅含脱敏任务及账号/绑定 ID |
| 连接复用 | 新账号读取使用独立池；复用时检查实际角色权限/OID，注入的额外列写权限被拒绝 |
| 迁移/历史 | 新增目录迁移 003；旧 v1 目录与旧 v2 已批准待开通授权分别无损升级、重复迁移通过；原 001/002 与旧元数据迁移不改写 |

最终场景 `0e73d8c4ef` 的元数据中有 23 个开通任务：12 VERIFIED、6 FAILED、4 CLEANUP_PENDING、1 OUTCOME_UNKNOWN。12 条 NativeAccount 和 12 条实际观察对应成功核验，当前 11 ACTIVE，另一个在资格撤销测试中成为 REVOKED。所有 ACTIVE 版本都有账号、绑定、观察和开通任务证据，缺证据计数为 0。管理审计身份均为 `mcpguard_provisioner`，没有冒充申请人。

固定提供方在两套 PG 真实创建 12 + 3 个原生角色，包含失败与未知窗口的测试角色。第一套中 4 个迟到/失败角色已 NOLOGIN，仍保留待清理事实；第二套中 1 个角色保留了故意注入的列写权限，读取拒绝已被断言。保留这些故障状态不表示自动恢复或清理完成。
