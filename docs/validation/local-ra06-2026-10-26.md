## 实现和实际后端证据

| 项目 | 本轮结果 |
|---|---|
| 租约及代次 | 首次派发使用 30 秒数据库租约；恢复只领取已过期且到达重试时点的任务。nonce/generation 同时参与完成、失败、激活及补偿检查，旧进程不能修改已由新进程恢复的结果 |
| 崩溃恢复 | 真实 SIGKILL 覆盖建号前、建号后、权限核验后及原生清理后；重启后仍使用同一加密计划、账号、HMAC 和秘密版本 |
| 未知结果 | 核对原生账本、计划和角色 OID，再用实际个人凭据核验权限。创建回执丢失后恢复原账号，既不换名也不再次调用 Create |
| 永久封存 | 原生建号、核对和清理使用同一账号事务锁。确认不存在时封存原计划，实际迟到 Create 被拒绝；原生创建已提交时核对读到该提交事实 |
| 迟到结果 | 资格移除、配置版本变化、主体禁用和到期先发生时均不激活。恢复检查与最终激活之间撤权仍被拒绝，终止授权只进入清理 |
| 有限清理 | 仅处理原生账本/OID 匹配的 PROVISIONED 账号，禁止新登录并撤回本模板权限；清理不可用或回执丢失保持待重试，实际确认后才 CLEANED |
| 次数与人工状态 | 核对/清理各最多 6 次，5 至 60 秒退避。最后一次领取中断后使用 FINALIZE 结束元数据，无第七次原生调用；无法确认的所有权、计划或效果进入 MANUAL_REQUIRED |
| 托管边界 | PREEXISTING 只核验，不改变密码、LOGIN 或权限；未托管碰撞、同名不同 OID、计划密文损坏和私有端点替换均不自动接管或误清理 |
| 审计及回执 | 每代尝试事件不可改写，管理审计身份为 mcpguard_provisioner。关键恢复审计失败不提交成功结果；原生清理已发生但元数据回执未确认时仍待核对 |
| 无损升级 | 真实旧 v3 UNKNOWN 任务及密文计划迁移到 v4 后原字节不变，generation=0 不冒充历史尝试；首次真实核对后追加 ACTIVE v2。旧 v1/v2 升级及旧功能回归继续通过 |

最后另执行一次真实 CLI recover-once，处理了 2 个遗留到期任务，分别收敛为 VERIFIED 和 CLEANED。两套 PG 的提供方账号账本在批次前后均合计 37 条，未创建新身份。最终 54 个开通任务为 23 VERIFIED、14 CLEANED、9 FAILED、8 MANUAL_REQUIRED；没有剩余 EXECUTING、OUTCOME_UNKNOWN 或 CLEANUP_PENDING。

8 个 MANUAL_REQUIRED 是明确的预期反例，覆盖重试耗尽、最后一次领取中断、未托管/替换角色、计划损坏及目标不符。保留这些状态不表示它们已人工处置。另有未派发的待开通授权属于申请/审批夹具，恢复不会替它们获得首次建号资格。原始 grant head 状态快照不替代每次访问的当前资格检查。
