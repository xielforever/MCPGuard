## 2 两种入口的独立证明

原生 HTTP：宿主测试器在内存中消费真实 `mcpguard-http-helper headers` 的私有 JSON，通过返回的认证头完成真实 HTTP MCP initialize/initialized。prepare 只返回安全任务；真实 worker 随后私下领取、原子保存并激活两套资源。短 Context 初始 2 秒，worker 在不改变宿主缓存令牌的条件下续期，超过初始期限仍可使用。达到自然到期后旧缓存头拒绝，worker 不在宿主背后换头；显式重连回调新建 Context 并重验本地文件。

stdio：启动真实 `mcpguard-connect --private-auth-file --private-directory` 进程。initialize 声明实际 experimental 能力，tools/list/call 前有界同步，prepare 后通过私有 API 领取并验证激活。所有 stdout 行都解析为 MCP 帧；原有无私有参数模式继续通过完整旧协议回归。Context 自然到期后，下次调用前创建新 Context、重新提交有效文件并更新远程请求头，原远程 MCP session 不提供授权捷径。

两入口均验证文件缺失后重取同一包、主动关闭后的拒绝自动重建、显式私有修复、员工错配拒绝及单包撤销后另一个资源继续有效。主动关闭用实际 ACTIVE-to-REVOKED 状态确认，自然 EXPIRED 与 REVOKED 分开测试。副作用库存前后相同，不新增账号、开通任务、授权或包。

stdio 网络故障：代理只截断一次实际 claim 的消费后响应。prepare 的原始成功结果保留，并附安全 `PENDING_PRIVATE_SYNC / PRIVATE_SYNC_ONLY / businessRequestReplayed=false`；没有第二次自动 claim。后续只运行私有同步，通过同包替代 ticket 恢复文件，不重新 prepare 或开通账号。原 RA-08 的网络未到达、响应丢失和并发一次领取继续回归。

## 3 模型不可见及能力边界

宿主私有头回调是专用通道，成功输出包含真实员工 Authorization 与 Context 头，不能当作模型工具输出。测试器消费这些私有字节后只保存安全检查，不打印或加入 MCP transcript。独立 worker 不输出私有值；交付 proof 只在生命周期 API 使用，不发送给普通 MCP。

stdio 检查当前令牌、Context token、实际缓存包片段与私有字段，包括 JSON-in-text，再把安全结果交给协议层；错误为固定安全信息。原始 MCP、连接器 stderr、worker 输出、网关日志和审计按实际私有值检查，无令牌或包内容命中。包只在服务端解密，组件不连接原生 PG。

能力声明区分 NATIVE_HTTP_HELPER、STDIO_PRIVATE、URL_ONLY。HTTP 需要宿主私有钩子与独立 worker，换头需要重连；stdio 在内部每次远程请求更新头。URL-only 不宣称自动私有交付，多资源权限始终以服务端当前授权为准，客户端自报能力不能授予权限。没有宣告 sampling、elicitation、Tasks 或任意版本转换。

同系统用户拥有任意文件读取/进程执行能力时，目录 ACL 不提供模型与用户进程之间的隔离。Windows 11 项为原生文件、缓存、私有头及控制器执行证明，不计为某个命名 coding 产品完成宿主私有钩子验收。
