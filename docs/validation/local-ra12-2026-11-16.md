## 3. 用例与断言

| 用例 | 覆盖的完成条件 |
|---|---|
| `TestControlledWriteNeedsAnotherApprover` | 计划冻结为 DEFERRED；申请人自批被拒；未批准不得派发；他人批准后只有申请人显式 resume 才执行，结果 `UPDATED`、版本 +1；同一单二次 resume 被拒（单次派发）；`write_audit` 至少 3 类事件与 `write_requests.state=SUCCEEDED` 均能关联到该计划 |
| `TestControlledWriteRejectsVersionConflict` | 第一次写入成功后，持旧版本的第二个计划派发得到 `FAILED / VERSION_CONFLICT`，原生行不被覆盖 |
| `TestControlledWriteRejectsRevokedCredential` | 签发后撤销凭据，再派发被拒（派发前凭据/绑定复查生效） |
| `TestControlledWriteRejectsNonReviewer` | 非审批人批准被拒，数据库 `CHECK(decided_by <> subject_id)` 兜底 |
| `TestControlledWriteRejectsBindingChange` | 批准后禁用该身份的绑定，旧计划 resume 被拒（RA-AC-15：批准后绑定变化使旧计划失效） |

## 4. 安全不变量

- 写身份为独立受限 PG 账号：仅 `SELECT,UPDATE` on `resource_demo.items`，
  `default_transaction_read_only=on`、`row_security=on`，只命中 `owner_update`
  行策略（`USING/WITH CHECK owner_name = CURRENT_USER`）。
- 读身份保持 SELECT-only，未被授予表写权限或 SECURITY DEFINER 的 EXECUTE。
- 写工具 `pg.update_note` 默认不注册，仅在 `MCPGUARD_RESOURCE_WRITES=enabled`
  且已启用读能力时可见。
- 开通 provider DDL 升级为 v3（校验和固定）；既有环境需显式重装 provider，
  不会自动升级。
- 契约升级为 0.2.8（`ProvisioningTarget.template` 枚举新增
  `PG_OWNER_UPDATE_V1`），0.2.7 已按字节归档在 `docs/specs/v0.2/history/0.2.7/`。
