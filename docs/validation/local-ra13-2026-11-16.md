| 用例 | 覆盖的完成条件 |

| `TestRevocationCredentialStopsNewAcquisition` | 撤销文件/凭据后：租约 REVOKED、影响计数=1；持旧 context 再领取新文件被拒（`ErrDenied`） |

| `TestRevocationResourceDisablesBindingsAndGrants` | 撤销资源后：资源头禁用、绑定全部禁用、grant/租约级联撤销；再领取被拒 |
| `TestRevocationAnotherReplicaSeesTheEpoch` | 撤销后授权 epoch 前进；用第二个独立连接池（副本替身）读取该凭据状态仍为 REVOKED，证明撤销经共享权威状态对副本生效 |

## 4. 实现与安全边界

- 入口为特权 CLI `mcpguard-catalog revoke`（迁移连接），不经 MCP 工具；运行时角色不获得撤销相关表权限。
- 每次撤销单事务：`lock_auth_epoch_exclusive` → `advance_access_epoch` → 级联终态 → `revocation_audit` 审计（actor、目标、affected counts、原因密文）。
- 已撤销的对象不可复活：租约/ticket/context/grant 的守卫触发器只允许单向终态流转；身份绑定可从启用改为禁用，不能反向重启用。
- 撤销不等待原生清理；清理与在途停止按 RA-14 处理，避免把"网关拒绝"误报成"后端已停止"。
