## 2. 未完成：recovery fence 与恢复点核对

完成条件"恢复旧备份不复活授权/包/写资格"需要**元数据库之外的锚点**，否则旧备份会连同 fence 一起恢复。当前做法与缺口：

- 现有 `account_fences` 是原生侧**永久封存**（ABSENT/CLEANUP/CONFLICT），只回答"该账号是否被永久封存"，不能回答"元数据是否被回滚"。
- 待实现设计（建议）：
  1. 在业务 PG 的 `mcpguard_provision` 增加按 org 的 `fence_state(org_id, generation)`；
  2. 签发/激活/派发前，读取原生侧 generation 与元数据记录的 generation 比对；
  3. 原生侧更高 ⇒ 元数据疑似回滚：拒绝签发/派发，要求运营方执行 `restore-verify` 重新核验撤销与账号事实后才更新元数据记录；
  4. 撤销证据缺失时废止旧 `issuerEpoch` 并重核授权。
- 该设计需要 provider 私密配置与业务 PG 连接（与 RA-14 的 cleanup 同一入口），属下一步实现。
